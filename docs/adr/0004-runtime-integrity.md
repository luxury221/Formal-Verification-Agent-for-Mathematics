# ADR-004：内容快照与运行环境完整性门禁

日期：2026-10-19。状态：已采用，MRA-016。

后续范围更新：ADR-007 将 `evals/nat-arithmetic-v1/cases.json` 和其数据集 manifest 加入固定文件封存；依赖归档与缓存重新核对，旧/新摘要见 `artifacts/nat-evaluation-seal.json`。原 P0 验收页保留历史环境摘要。

原实现只将 Lean 主程序与 Mathlib manifest 的摘要写入环境指纹。动态库、导入的 `.olean`/`.olean.private`/`.ir` 或启动器变化时，旧回执仍可能被接受。现在环境指纹包含实际文件清单的内容摘要，并在后端初始化、每次运行前、每次证据评估前重新读取文件校验。

快照覆盖 Lean 整个安装树、Mathlib 及其八个依赖的源码和构建树，包括 Cache 可执行文件；递归排除 `.git` 传输元数据。清单记录文件 SHA-256、权限、目录及符号链接目标，拒绝新增、删除、越界链接、内容或权限变化。读取时还检查文件是否被并发替换；不使用大小/mtime 缓存代替内容校验。另绑定隔离启动器、黄金案例、环境/公理策略及下载回执。

`seal_runtime.py` 是显式准备操作。它先核对固定 SHA-256 的官方 Lean 归档，逐文件比较已安装内容，并拒绝安装树中的额外文件；再核对九个源码归档的下载摘要及已安装源码、commit 标记和 manifest。源码归档中的文档符号链接由既有 materializer 省略，允许缺失这些别名。最后用已核验的官方 leantar 在临时目录重新解包 154 个已下载缓存包，比较实际安装文件。临时目录退出时删除，不更改正在使用的依赖。

首次建立基线不会执行尚未核验的 Lean 主程序或 Cache 工具。随后对可信 Lean、Python、unshare 和 shell 做 `ldd`，绑定这些入口及其解析出的宿主 ELF 依赖。实际检查时先验证内容，再查询 `lean --version`。检查进程清理继承环境，避免 `LD_PRELOAD` 等变量改变装载行为。

清单位于 `.runtime/runtime-snapshot.json`，独立本机锁位于 `lean_workspace/runtime-lock.json`。两者均为机器相关的本地资产，不纳入版本控制。加载后的后端也保存两份文件的摘要，运行期间修改清单或锁会被拒绝。验证操作从不重建清单；已有基线只能通过显式 `seal_runtime.py --replace` 重新做归档核验后替换。每次运行复制清单进自己的工件目录，并将其文件哈希纳入内部签发回执。因此替换全局快照后，旧报告仍保留旧环境清单。

完整性失败导致 `POLICY_BLOCKED / UNKNOWN / E2`；运行前发现问题时不启动 Lean。证据门禁独立复查，已经完成的真实证明也不能在依赖变化后晋升 E3/E4。环境指纹变化使旧回执无法用于新环境。新接口 `python3 -m mra environment` 可单独验证当前基线。

同时收紧固定案例接口：案例字典、Claim 和 Formalization 必须共同匹配仓库中的确切版本，禁止利用额外传入的形式化表达式绕过固定 Lean 输入边界。任意候选形式化应等待独立输入与复验接口。

代价：校验读取整个依赖树，增加本地 I/O；当前不通过跳过内容校验降低开销。回执分别记录 `integrity_seconds`、检查进程的 `elapsed_seconds` 和两者所在检查步骤的 `total_elapsed_seconds`；证据门禁的再次校验另计入调用总耗时。未来可用受信的不可变镜像/文件系统降低重复 I/O，但需要等价的篡改回归。

边界：源码/缓存来源依赖固定 commit 的 HTTPS 获取及其本地下载摘要，没有上游独立签名或可复现构建证明。Cache 本地构建产物被绑定，但没有独立构建复验。Linux 内核、Python 标准库、全部 `/usr` 内容及同一宿主用户仍属于可信基础；列举的 ELF 依赖检查不等于封装完整操作系统。校验与执行不是原子文件系统事务，无法防御恶意宿主并发修改后恢复内容。具有代码和本机锁写权限的进程不在防护边界内。任意不可信 Lean、持久签名、不可变工件和独立复验继续由 MRA-022 处理。
