# ADR-005：结构化 Formalizer 与模型服务协议

日期：2026-10-19。状态：采用，完成 MRA-017；提供 MRA-019 的候选审核基础。

后续更新：ADR-006 扩展本地持久有效状态、撤销、源版本唯一性和显式修订关系；下文关于纯 JSON 历史、尚无状态归并的描述记录初始实现。

P0 只接受确切仓库案例。P1 先增加独立的形式化候选层，记录用户陈述及上下文、定义域、量词、附加假设、解释、未解决的问题与生成版本。候选层不依赖 Lean 安装，使用 Python 标准库，不复制第三方框架实现。

`Formalizer` 提供 `formalize_claim`、`formalize_step`、`suggest_clarifications`；`ModelService.generate` 使用类型化请求、预算、生产者身份、token 用量和响应。请求指纹绑定任务、原文版本、上下文、预算及输出协议；适配器返回的请求指纹必须相符。模型身份由服务适配器提供，生成的 JSON 不得自报生产者或可信等级。

响应只允许三种内容状态：候选就绪、需要澄清、不支持。严格解析拒绝重复键、未知/缺失字段、非标准 JSON 常量、错误版本、空定义域、未知量词及不一致状态；最多三种候选、三个澄清问题。模型附带 `PROVED`、证明代码、公理或对齐结论等额外字段会被拒绝。候选中的 Lean 字符串只作为数据保存，当前接口没有执行它的路径。

解析成功不代表语义正确：变量、定义域和假设也是候选的主张，仍需审核确切 Lean 陈述。`CANDIDATES_READY` 保持 `UNKNOWN / E0`；歧义为 `NEEDS_CLARIFICATION / E0`；不支持为 `UNKNOWN / E0`。超时、基础设施失败和无效回包分别保留 `TIMEOUT`、`EXECUTION_ERROR`、`POLICY_BLOCKED`，均不判定原命题真假。

默认 CLI 使用 `FixtureModelService`，按完整原文和上下文精确匹配自有样例，并将 `kind=fixture`、样例文件 SHA-256 和零模型 token 用量写入工件。它没有自然语言解析、真实模型推理或证明搜索能力；未收录文本返回不支持，步骤模式亦返回不支持。真实服务可替换该协议实现，但本阶段没有网络适配器、付费调用或模型权重。

`SourceClaim.revise` 保留源 ID、递增版本并改变内容指纹。CLI 的 `--revise` 核对上一工件，拒绝跳号、旧版本或改换源 ID。没有指定修订关系的独立输入仍按内容指纹隔离；全局命题 ID/版本唯一性与任务幂等性属于 MRA-021。

候选审核是独立具名声明，绑定整个草稿及选定候选的指纹。原文、上下文、变量、假设、表达式、生产者或版本变化都会使旧记录失效。歧义未解决时不能接受任一备选。审核接受或拒绝均保持 `UNKNOWN / E0`，不直接转换成 `Alignment` 或内核证据；后续需在独立验证后接入 MRA-019/MRA-022 的 E4 流程。

工件保存原文、完整请求、原始响应、结构化草稿和文件摘要；读取时重算摘要与元数据。审核记录使用新文件追加，记录实际 UTC 时间，保留历史声明，不覆写草稿。这是本地审计记录，没有实现审核者登录、审核撤销/有效状态归并或抗恶意管理员的持久签名。公开服务与跨租户可信存储尚未提供。

预算限制序列化输入字符数、输出字节数、适配器报告的输出 token 数和响应期限。服务实现必须将超时和输出预算传递给网络/推理进程；Formalizer 还会拒绝逾期返回或超限内容。当前同步 Python 协议本身不终止一个永久阻塞的第三方实现，未来真实服务需提供可取消传输或进程边界。错误原因不会回显传输异常中的私密连接信息。

测试分组明确区分模型协议 mock、真实本地 fixture/文件工件、无 Lean 环境下的 CLI，以及既有真实 Lean 回归。mock 和本地样例均不计为真实模型能力或数学证明成功率。
