# ADR-006：审核有效状态、撤销与修订事务

日期：2026-10-19。状态：采用，扩展 MRA-019；身份认证及独立验证后的 E4 接入仍待完成。

仅追加 JSON 审核文件无法确定当前采用哪一条声明，也不能原子地处理修订与审核并发。本阶段采用 Python 标准库 sqlite3，使用本机 SQLite 3.37.2，无新增 pip 依赖。许可证、用途和部署限制记录在 `docs/security/license-inventory.md`。

`artifacts/formalization/review-state.sqlite3` 是本地审核及源版本关系的权威账本。草稿目录、确切内容指纹、manifest 摘要、源 ID/版本/指纹和显式修订父目录写入同一事务。源的 `(id, version)` 不得指向两份内容；初始版本须为 1，后续修订须由当前版本按 `SourceClaim.revise` 产生。允许同一当前源版本的不同生成请求，审核分别绑定各自草稿，不自动转移。显式父目录属于这次草稿注册；同一源版本再次生成不会成为另一条源修订。

写入使用 `BEGIN IMMEDIATE`、外键和 `synchronous=FULL`，由 SQLite 串行分配事件序号。读取状态在一个事务快照内完成。排序依据提交的事件序号，UTC 时间仅用于审计。两个并发修订至多一个推进源版本；与修订并发的审核或先提交后失效，或因旧版本而被拒绝。

每条审核包含全局唯一 `event_id`、完整具名声明和确切草稿/候选指纹。`--event-id` 可由调用者提供以重试；同一 ID、同一内容返回原事件，不再追加，不同内容拒绝。随机生成 ID 只标识一次调用，调用者若需要跨进程恢复，应在首次操作前自行保存稳定 ID。本实现仅提供审核事件幂等，不宣称实现 MRA-021 的持久任务调度。

对每个候选采用事件序号最大的审核声明。接受和拒绝均可被后续明确审核覆盖；不同本地具名审核者也适用同一顺序规则，没有投票、角色或多人审批策略。多个候选分别有状态，不自动选出一个用于证明。

撤销必须指明原审核 ID、同一草稿/候选指纹、原审核者姓名及说明。它可以撤销当前或历史声明，也可撤回已经过期的源版本声明；不能撤销另一条撤销，不能再次撤销同一审核。这里核对姓名只是本地具名声明，没有登录、凭证或权限认证。

最新审核被撤销时状态为 `REVOKED`，不会恢复此前接受或拒绝。撤销一条更早的审核不影响较新的审核。之后只有新的明确审核才会改变当前候选状态。

源修订事务提交后，该源所有旧版本草稿均为 `SUPERSEDED`；历史仍可查看，但不再有有效接受。新版本从 `UNREVIEWED` 开始。相同源的旧内容不能重新作为初始输入恢复；旧事件幂等重试只返回历史声明，不恢复其有效性。报告同时显示 `status`、`last_review_status`、`last_review_id`、`effective_review_id` 和 `accepted`，避免把历史 `ACCEPTED` 误读为当前可用。

草稿文件先写入并 fsync，再注册事务。文件写完但事务失败时可能留下无效力的孤立目录，读取为 `UNREGISTERED`，可检查后通过显式注册恢复。提交后的事件 JSON 是可重建导出，不参与状态归并；删除、篡改或添加 JSON 均不能授予审核状态。若提交成功、导出前中断，`formalization-report` 仍能看到已提交事件；用原 ID 和参数重试可重建导出。命令失败不必然代表事务未提交。测试覆盖事务回滚、真实子进程 SIGKILL 以及导出失败；没有模拟整机断电或存储设备故障。

旧版草稿可以直接查看，状态为 `UNREGISTERED`，修改前须 `register-formalization`。旧 JSON 审核没有权威顺序、可信注册关系或持久授权，因此不自动导入有效审核；原文件保留，注册后须重新明确审核。旧修订按版本先注册父目录，再用 `--revise` 注册子目录。数据库缺失时也不从 JSON 猜测或恢复授权；备份应在停止写入后一起保存数据库和草稿目录。

每次读取重新验证草稿文件摘要、账本绑定的 manifest 和完整草稿指纹，并重新验证事件结构、候选绑定及撤销关系。数据库或 manifest 符号链接、未知数据库版本和损坏数据拒绝处理。SQLite 及本机用户仍受信，持有本地文件权限的人可修改数据库或删除历史，本实现没有防恶意管理员签名、不可变存储或跨租户授权。SQLite 动态库属于现有宿主可信基础，没有加入 Lean Worker 的封存工具链。

所有候选接受、拒绝和撤销仍保持 `UNKNOWN / E0`，不会生成 `Alignment`、执行任意候选 Lean 或改变既有 P0 证据门禁。完整 MRA-019 仍依赖审核身份、MRA-022 独立检查与持久签发；本地账本不能替代这些要求。
