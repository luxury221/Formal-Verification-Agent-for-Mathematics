# ADR-009：独立进程中的证明数据内核重放

日期：2026-10-19。状态：采用，交付 MRA-022 的独立进程复验部分。任意外部 Lean 能力限制、认证和持久签发尚未完成。

此前目标类型和公理审计与候选代码在同一 Lean 进程中执行，不能将日志中的审计声明当作抵抗恶意元编程的安全边界。增加第二个隔离进程，从数据重建本地声明，并通过内核重新检查精确目标。两次检查采用同一封存的 Lean 4.35.0 内核；本决定不声称使用了不同实现的外部验证器。

候选阶段使用官方发行包中的 LeanExport.Basic，导出本模块所有本地声明及其传递依赖，格式为 NDJSON 3.1.0。宿主要求唯一且有序的导出边界、严格 JSON、固定 Lean/格式版本，限制为 512 KiB 和 12,000 行。导出文件作为不可信数据保存，不编译为插件或候选 .olean。

第二阶段运行封存的 `lean_workspace/replay-checker.lean.in`，只导入受信的 Mathlib.Data.Nat.Basic、LeanExport.Parse 与 Lean.Replay。目标表达式只能来自原有仓库 allowlist；模板由宿主插入确切目标。执行器仍同时核对完整案例、Claim（包括前提）和 Formalization，不增加任意用户/模型 Lean 的执行入口。

检查器先在封存基础环境中解析目标，再读取导出数据。基础环境已有的常量以受信版本为准，忽略导出的同名内容，避免用序列化数据替换已导入公理或引理。新增声明必须位于 MraCandidate 命名空间，只允许 safe、非 partial 的 theorem/definition/opaque；拒绝新增 axiom、unsafe、partial、归纳声明及其他声明种类。Lean.Replay 对筛选后的声明逐个调用内核检查，随后再次添加以 MraCandidate.result 为证明、以宿主精确目标为类型的桥接定理。桥接失败不能由审计日志补救。

检查器对目标及全部新增声明独立收集传递公理，执行允许/禁止清单。EvidenceGate 要求两个进程均成功、进程号不同、重放声明数为正、精确目标/声明种类正确、两个公理审计一致且没有本地新公理，然后才可授予 E3。具名、版本绑定的语义对齐继续是 E4 和 PROVED/REFUTED 的独立条件。编译失败、数据错误、内核拒绝、超时或取消均不能形成数学反驳。

两阶段共用原候选尝试的 Worker 墙钟预算；完整内容哈希与初始化另外记录。一个候选尝试至多启动两个 Lean Worker，不因增加重放而获得第二次生成、修复或扩大的执行预算。运行前、重放前和证据晋升前继续核对封存内容。新模板与策略加入运行封存，变更必须显式重新比较官方归档、源码与缓存后再封存。

第二阶段沿用 namespace/chroot、无网络、只读输入和工具链、双线程、16 GiB 地址空间及文件大小限制。两个阶段均继承任务 worker 锁，异常、超时、取消均终止并回收所启动的进程组。任务新增 REPLAY_PREPARING、REPLAY_RUNNING 阶段；恢复仍不从旧 JSON/HMAC 导入证据，重试必须重新运行两阶段。

回执绑定两个阶段的源、证明数据、策略、标准输出/错误和环境清单摘要；任务历史报告继承这些工件。HMAC 仍仅在当前 Python 后端实例中有效，保存的回执不是持久签名。数据库、宿主所有者、内核、Python 标准库及封存的基础库仍受信，未解决恶意宿主并发替换、公开多租户配额或来源签名问题。

任意恶意 Lean 代码可能省略未导出的本地声明；重放只能审计实际提供的数据。当前导出收集由批准的仓库代码控制，不能将本阶段攻击数据测试解释为已完成任意外部 Lean 的语法/能力安全边界。后续开放生成证明前必须另行制定该边界和攻击验收，不得取消当前 allowlist。

许可采用既有官方 Lean 4.35.0 归档中的 Apache-2.0 API，没有复制第三方实现、下载依赖或启用 bundled 外部 checker。具体记录见许可清单。原始失败运行及修正模板后的重新封存均保留历史，不能把失败日志当成验收通过。

回滚须停止任务领取并保留新旧工件。若改回原策略，需明确恢复对应实现及模板/策略范围，再显式重新封存；不能只替换锁文件或用旧报告授予新证据。旧请求绑定旧策略/快照，不能在新环境中静默继续。
