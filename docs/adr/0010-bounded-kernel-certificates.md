# ADR-010：固定目标的受限内核表达式证书

日期：2026-10-19。状态：采用，交付 MRA-022 的受限证明数据输入增量。沿用 ADR-009 的独立进程重放和证据门禁。

已有复验可以检查候选导出的声明，但执行器仍只能运行仓库参考源；直接开放模型生成的 Lean 源会带来命令、宏、tactic、元编程和声明导出完整性的额外边界。新增结构化证书入口，让调用者提供纯内核表达式数据，由受信模板构造唯一目标定理。该入口接受不同证明项，目标、方向和语义对齐规则仍由宿主控制。

首期只启用两个固定目标：nat_add_zero 的原命题与 false_all_nat_zero 的完整否定。案例字典、Claim（含假设）、Formalization 仍须精确匹配仓库记录；不能提交新目标、减弱命题或绕过 Nat 预留组选择。旧 `check`、基准与持久任务继续执行未改写的仓库参考。证书使用独立的 `check_certificate` 方法和 `check-certificate` CLI；本轮不将证书加入持久队列或参考评测分数。

证书格式 kernel-expression-certificate-v1，包含 schema、Claim/形式化指纹与 proof。表达式仅允许 const、app、lam、forall、bvar、nat、sort 七种构造，不包含源代码、tactic、声明、宏、元变量、投影插件或外部模块路径。宿主严格检查字段、名称、整数、变量作用域、JSON 重复键，限制 64 KiB、2,048 个节点、深度 64、宇宙层级 0–8、自然数字面量 0–2³²−1，并对规范化后的大小再检查。文件读取有界，深层 JSON 解析失败转为受控错误。

第一阶段执行封存的 certificate-checker.lean.in，只对宿主固定目标进行 elaboration，证书字段不拼接进 Lean 源、不交给 parser/elaborator，也不通过 Lean 运行时求值器或编译器执行。模板从基础环境查找常量，拒绝不存在、unsafe 或 partial 常量，将 JSON 节点直接构造成 Lean.Expr。唯一候选声明为 MraCandidate.result，其类型是宿主目标，由 kernel.addDeclCore 检查；内核可以为类型检查进行纯表达式归约。常量名称指向 IO 等类型也只是数据，不能启动 IO；类型错误会被内核拒绝。

构造器没有新增 axiom 的能力；对受信环境已有公理的引用仍由目标传递公理审计和原有允许/禁止清单控制。sorryAx 或 Lean.ofReduceBool 不能形成可信证据。目标定理检查成功后导出它的传递依赖，第二个隔离进程按 ADR-009 重新检查证明数据、精确目标和公理。证书入口只构造一条本地目标声明，消除了让任意外部源自行收集本地声明的需要。该结论仅适用于这七种数据构造的路径，不扩展为任意 Lean 源安全性保证。

EvidenceGate 要求显式输入模式，证书模式额外绑定 input/certificate.json、规范化内容摘要、目标指纹和 candidate_source_executed=false 审计；仍检查两阶段成功、独立进程、公理一致、完整工件和版本绑定对齐。缺少审核只能 UNKNOWN/E3；具名对齐后方可 PROVED/REFUTED/E4。类型错误是未验证结果，超时和取消不代表数学反驳。

两阶段共享原 Worker 墙钟预算、隔离及清理逻辑，没有第二次生成或自动修复。模板与模式/目标策略纳入封存，更新后显式重新核对已批准官方归档、源码和缓存。宿主 Python、文件所有者、内核、SQLite、受信库及 Lean 实现仍属于可信基础；持久签名、身份认证、不可变存储和服务级配额保持后续范围。

`certificate-target` 在无 Lean 时提供原文、精确目标和证书头，只是 E0/UNKNOWN 的描述；`check-certificate --input` 执行真实验证。示例证书为作者构造的自有开发资产，真实模型调用为 0，不计为模型生成能力。依赖采用既有 Lean 公开 Expr/Json/kernel API，无新增下载、运行依赖或外部实现复制。

回滚时停止证书调用，保留工件与封存历史；移除证书模式、模板和相关入口后显式重新封存。旧策略/快照绑定的任务和回执不能静默转移到新环境。证据历史仍无持久验签能力，重新认证必须运行新检查。
