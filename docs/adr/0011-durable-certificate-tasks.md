# ADR-011：固定目标证明证书进入持久队列

日期：2026-10-19。状态：采用。扩展 ADR-008 的输入种类，沿用 ADR-010 的全部证书能力边界。

同步证书入口已经完成两阶段真实 Lean 检查，但调用进程退出后不能用任务 ID 查询、取消或恢复。新增 `TaskStore.submit_certificate` 和 `task-submit-certificate`，复用现有任务、尝试、事件、事务及 Linux 单 worker 锁。此变更不开放新的数学目标或 Lean 源能力，也不连接模型服务。

新请求 `kind=kernel-certificate-check`，固定 `suite=golden`、`input_mode=kernel-expression-certificate-v1`。提交先按相同受限协议解析原始 bytes，再将规范化 UTF-8 JSON 文本（含末尾换行）及 SHA-256 一起保存在请求 JSON。文件路径不进入执行合同；原文件删除或改写不影响已经入队的内容。目标案例摘要、原文、形式化、假设、方向、具名对齐声明、预算、运行快照及策略继续冻结。提交仅解析数据和加载本机封存元数据，不启动 Lean 或模型，也不授予证据。

证书规范化后才计算请求指纹，因此 JSON 空白及键顺序差异是同一请求；证明项、目标、审核者、预算或模式变化必须使用新请求 ID。参考任务和证书任务共享提交 ID 命名空间，不能用同一个 ID 切换输入模式。初次及重试合计仍最多三次，预算和证书均不可在重试时更改。

数据库仍使用 schema v1。既有 `repository-reference-check` 请求的字段和指纹保持原样；新信息存放在现有 request JSON，不修改表或导入历史报告。旧 worker 重建参考合同后无法匹配新证书请求，应拒绝执行；恢复和取消只处理状态，不解释证明。部署时使用同一版本的提交和 worker 程序。

worker 显式分派已知 kind，并在初始化 Lean 后端前重建整个请求。证书重新进行大小、格式、表达式作用域和精确目标绑定检查，比较规范化正文、摘要、模式、案例、策略和运行快照；未知 kind 或任何合同漂移都失败关闭。通过后将数据库中的正文 bytes 交给现有 Harness。后端及 EvidenceGate 仍核对仓库案例、Claim、Formalization、两进程、公理及语义对齐，队列不自行签发 E3/E4。

证书两阶段继承原任务锁，共用该尝试的 Worker 墙钟预算并响应取消。终态事务再次检查取消；即使单次检查已写出 PROVED/E4，先提交的取消仍使任务发布 UNKNOWN/E0。监督进程在终态提交前被杀死时，恢复只记录 INTERRUPTED，不导入磁盘上的成功报告。显式重试从冻结证书重新执行两阶段，使用新工件目录；不会恢复到第二阶段或复用旧成功回执。

证书文件已经进入后端回执的文件摘要，现有任务归档机制自动将其纳入持久摘要。历史查询发现证书或其他已记录文件变化时，顶层结果为 UNKNOWN/E0，历史尝试保留。历史摘要核对不是当前环境重新认证，HMAC 仍只在签发后端实例内有效。

没有新依赖、下载、模板或政策变更，不需要重新封存 Lean/Mathlib 运行快照。SQLite、本地所有者、Python、宿主及同一 Lean 内核实现继续受信；没有身份认证、持久签名、分布式调度、后台自动重试或模型生成恢复。验证记录见 `docs/evaluation/certificate-task-results.md`。
