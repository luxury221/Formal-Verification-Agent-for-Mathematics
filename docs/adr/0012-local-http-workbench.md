# ADR-012：复用持久队列的本地 HTTP 工作台

日期：2026-10-19。状态：采用。范围：MRA-023 的单机、固定目标纵向流程。

CLI 已具备版本绑定、持久任务和两阶段真实 Lean 检查，但用户需要在终端之间查看命题、查询进度及提交语义对齐。新增 `python3 -m mra serve`，提供本地 HTTP 协议及项目自有 HTML/CSS/JavaScript 页面。所有提交仍调用 TaskStore，worker 仍调用现有 Harness 和 EvidenceGate；HTTP 层不能自行写入数学结论。

本阶段使用已有 Python 3.10 标准库 http.server、threading、secrets、sqlite3，不新增运行依赖、网络资源或外部 UI 实现。页面使用本机提供的静态文件和系统字体，没有 CDN。服务地址固定 127.0.0.1，CLI 只允许选择端口；这是受信本机所有者使用的开发工作台，不是多租户生产服务器。

请求处理线程只做有界解析、状态事务和工件读取。单独的非 daemon worker 线程调用 TaskStore.work_once，按原顺序处理已排队的 CLI/HTTP 任务；两阶段检查继续在原隔离子进程执行并继承队列锁。另一个 CLI worker 持锁时等待，不强制接管。服务重启会恢复中断状态，保持 UNKNOWN/E0，不自动重试；新的尝试仍需明确请求。正常退出等待当前有限尝试完成，然后停止领取新任务；异常退出继续受原残留子进程锁和恢复规则约束。

HTTP 新提交仅支持两个既有黄金目标，可选择完整仓库参考或受限表达式证书。原文、实际检查表达式、方向、假设和目标指纹由服务返回。提交必须带显示版本的两个指纹；证书以原始 JSON 文本传输，服务重新解析，不能让浏览器 JSON.parse 消去重复键。请求体限 192 KiB，内部证书仍限 64 KiB/2048 节点/深度64。未知字段、源代码模式及禁用目标拒绝；不存在任意文件路径读取或上传执行入口。

语义对齐必须为明确 confirmed=true 的具名本地声明，并绑定显示的目标指纹。未提供声明时仍只能 UNKNOWN/E3。浏览器在查看旧任务或切换目标时清空确认；E3 后的“确认映射并重新验证”创建新任务并重新运行两阶段，不修改旧任务，也不把 Formalizer 审核账本直接作为认证。姓名仍不是已认证身份。

Host 必须精确匹配本次监听地址，浏览器跨源/跨站请求拒绝。写操作必须同时提供匹配 Origin 和本次服务启动随机生成的 CSRF token；不开放 CORS，响应 no-store，页面 CSP 限同源脚本/样式/连接并禁止嵌框。正文需唯一 Content-Length 和 JSON 类型，不接受 Transfer-Encoding。证书、用户输入和 token 不写入访问日志。token 用于浏览器请求隔离，不能抵抗恶意本机用户，不代替账户认证或持久签名。

新增 TaskStore.list_tasks 仅返回最近任务的执行元数据，不从未核对的历史行展示数学结论。具体任务查询复用 report 的工件摘要核对。证据接口仅对已提交且摘要相符的最新尝试提供报告/回执；再次读取时核对实际字节摘要，取消、恢复未提交及工件变化均不提供遗留成功报告。所有历史证据明确 fresh_attestation=false。

界面将运行状态、数学判断和证据等级分开，展示阶段、尝试、预算、用时、原式/完整否定、对齐声明、事件和历史工件。当前模型调用/费用为0；作者证书示例明确标注来源，不代表模型生成。没有引入一般自然语言求解、用户定义目标、论文上传、知识入库、身份权限或公开部署。

开发验证使用既有 Node.js 与 Microsoft Edge，通过标准 DevTools Protocol 自动操作真实页面并保存截图，不引入浏览器自动化运行依赖。版本、许可用途见依赖清单。协议见 `docs/protocols/http-workbench-v1.md`，验收见 `docs/evaluation/http-workbench-results.md`。
