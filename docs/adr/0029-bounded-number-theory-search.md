# ADR-029：在冻结验证边界外生成有界数论证明候选

日期：2026-10-27。阶段：MRA038。本地验收结果另见 [验收记录](../evaluation/number-theory-search-results.md)。

此前 gcd/互素入口要求手工填写完整证明项。蓝图 R4 要求逐步增加证明搜索，同时保留确切目标、完整前提、预算及失败记录。本轮增加独立候选生成器，组合现有 22 条受控引用；原编译器、验证器、执行器、运行封存及账本结构不修改。

采用迭代加深的反向规则匹配。输入是去掉 proof 的完整旧语言目标，允许精确假设、pair 和等价式的 mp/mpr；传递性的中间项从有限输入子项池中选取。默认深度 6、3000 步，最多深度 8、6000 步、32 个子项、0.75 秒协作式搜索墙钟。每个目标展开、规则匹配和实参枚举均计步；不任意扩展 Nat 项、不执行候选源码、不使用模型。现有语言不支持的合取消去、析取构造、归纳、任意战术与算术归一化继续不支持。

生成器不创建账本、不提交队列、不调用 Lean、不授予数学结论。输入和候选均经现有编译器的语法检查；这不等于类型证明。输出始终 UNKNOWN/E0，包含完整目标、候选、引用、预算消耗、来源摘要、请求及候选指纹、失败诊断。预算耗尽、当前规则不能处理或候选超过证明语言上限均不能作为反例。

前端独立面板允许在证明栏为空或 JSON 无效时发起搜索。用户明确带入后派发输入事件，清除原完整预览与语义确认，必须重新核对、具名确认，再由原真实候选检查及独立内核重放产生结果。输入/预算编辑、示例切换、历史带回均推进 generation；输入编辑后又恢复也会丢弃旧响应。搜索记录可导出，不自动保存到研究知识库；提交的新运行绑定完整候选正文，搜索过程来源需要单独保留导出。

候选生成代码放在可信证明边界之外，其后续升级不撤销此前已核验的同一完整证明。来源 SHA 是本地追溯标记，既非数字签名，也不保证运行中的内存代码与文件完全一致；证明有效性仍取决于原严格验证工件和语义对齐。本轮无新第三方依赖，无 Euler 代码或模型材料；沿用已记录的 Lean/Mathlib 版本及许可。

这实现的是明确语法内的有限引理搜索，不是读取任意 Lean proof state 的交互式战术搜索。是否拓展到归纳、一般定义或模型引导，应以新的领域目标、固定预算及含失败/未知的独立对照为依据。
