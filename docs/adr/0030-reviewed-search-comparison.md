# ADR-030：先审查生成候选，再进行可复核的搜索对照

日期：2026-10-27。阶段：MRA039。实际验收见 [结果记录](../evaluation/search-comparison-results.md)。

MRA038 能自动组合有限引理，但没有独立保存逐题搜索过程，也没有对照展示组合的作用。按照蓝图“以评估数据驱动演进”的原则，本轮增加作者可见、无参考证明输入的固定预算功能对照。16 道完整 Nat/gcd/互素目标来自项目作者；全部已查看，开发组 4 道、回归组 12 道，非独立持出或模型测评。

两种方案都使用原搜索器：direct 的证明高度上限为 1，composed 为 6；每次均最多 3000 步、32 子项和 0.75 秒协作式合成。direct 是很弱的单节点证明基线，仅可直接给出无证明前提的引用或精确假设；应用带证明前提的引理也需要更高高度。对照只展示证明高度放开的功能效果，不声称优于成熟证明器；两者实际消耗单独记录，相同上限不表示实际计算量相等。

准备命令先运行两种搜索并保存全部目标、所有候选及完整验证计划，不调用 Lean。具名审核者逐题审查后，以该计划指纹执行一次。新执行使用每轮独立检查目录和临时 SQLite 账本，继承原冻结 NumberTheoryStore 执行器；主业务仍为 13 个物理数据库，不把评测子结果混入日常实验、研究图或知识库。

执行持有原全局 worker 锁及本轮文件 lease；每候选最多一次实际检查与独立证明数据重放，共享 30 秒 worker，环境扫描另计。无候选的题目保持 UNKNOWN/E0 并进入完整分母。单轮最多 32 个方案/题目槽位；没有自动重试。相同确认重复命令只读取既有状态；不同核对者拒绝接管。中断或进程退出不从已有子工件补出整轮成绩，需要新准备、新审查才能另开一轮。

计划和报告使用单个原子替换的 JSON envelope，将内容与摘要一起发布，避免分开写 report 和 sha 的读取窗口。完整目标、来源与预算、所有结果的顺序及覆盖、子账本的确切计划和具名对齐、实际工件均需复核。检测到计划、数据、生成器或证据变化时写持久 invalidated 标记；文件恢复不复活。未完成、中断、故障及不可用状态均不显示完成统计。本地摘要仍不是签名，宿主和文件系统受信。

浏览器评测中心只读，展示逐题目标、两种方案候选、完整证据与导出，执行通过本地 CLI 完成；打开页面不搜索、不排队、不启动模型或 Lean。既有检查器、编译器、原搜索器、运行封存和既有测试保持不变。无新依赖、外部数据或 Euler 实现。
