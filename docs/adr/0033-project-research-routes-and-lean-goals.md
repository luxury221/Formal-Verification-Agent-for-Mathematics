# ADR033：同项目研究路线与实际 Lean 目标观测

日期：2026-10-27。阶段：MRA042。

原证明搜索、固定策略和反例实验各自可运行，但缺少同一研究问题内的完整路线记录。本轮在原 `/research` 项目与研究线下增加不可变任务图，统一提案、确认、检查、失败诊断、研究前置和实际目标观测。保留冻结验证器及旧证据协议，不迁移历史来源，不回填旧评测。

任务保存完整原问题、1–8 个节点、每个节点的完整变量/前提/结论和无环前置。原项目问题及分支上下文以指纹绑定。依赖仅约束研究推进，绝不成为额外 Lean 假设。每个引理与原问题都独立检查完整定理；所有引理通过不能自动证明原问题。

统一五类路线：现有有界引理组合、固定 omega、受控 gcd 化简、有限反例和固定 gcd 目标观测程序。提案及数值结果恒为 UNKNOWN/E0；每次检查均需核对完整方向、公式、证明、映射、预算及前置后具名确认。反例子检查证明完整否定，只有父尝试完成且原始 E4 工件有效才给原问题 REFUTED。

首期目标观测使用真实 Lean `Lean.Elab.Tactic.getGoals` 与 `Lean.Meta.ppGoal`，在同一 Lean 进程的 before、introduced、split、closed 四个固定位置采集。它是固定程序实验，不提供任意战术、交互会话、分支回退、归纳或会话恢复。pretty 文本用于诊断；数学证据仍来自完整候选类型/公理审计及独立证明数据重放。解析只接受行首诊断标记，排除 linter 引用采集源码的警告。

存储采用 `artifacts/research-flows/flow-*/` 的带摘要 JSON 信封、原子替换、fsync 和短时非阻塞 flock。每次尝试使用隔离子目录及子 SQLite 账本，沿用全局 worker 锁；主业务库数量保持十四个。备份必须包含任务信封和所有子账本、候选与重放目录，不能只备份主库。

每任务最多24份提案、16次检查，一次只执行一个尝试；每次候选和重放共享1–30秒 worker，完整性扫描另计，无自动重试。计划或记录损坏会持久标记，恢复旧文件不会恢复资格；父语境、来源和子工件变更停用研究绑定。撤销前置使依赖绑定失效，同时保留独立子证明的历史工件。监督进程中断即使已有成功重放，也不自动晋升父尝试。

保留 Lean 4.35.0、既有固定 Mathlib、许可证和内核策略，无新增第三方依赖、模型、外部数据、Euler 实现、训练或重新封存。本轮作者可见基础功能题不构成独立能力分数或四大期刊级问题求解证据。见[协议](../protocols/research-flow-v1.md)与[实测](../evaluation/research-flow-results.md)。
