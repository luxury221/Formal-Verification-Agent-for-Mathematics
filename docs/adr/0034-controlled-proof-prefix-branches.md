# ADR034：受控证明前缀与实际开放目标分支

日期：2026-10-27。阶段：MRA043。

ADR033 提供固定程序的四检查点观测，不能由用户选择下一步。本轮增加独立推演空间，绑定既有研究任务某节点的完整目标与研究前置。先真实读取初始目标，再从已观测的开放状态选择一个固定 tactic；每次在新 Lean 进程重建完整前缀，保留失败分支。该设计提供有限逐步推进，不声称恢复长驻 Lean 会话。

允许 intros、Nat.dvd_gcd、Nat.dvd_add、assumption、all_goals assumption、omega 和既有受控 gcd simp。禁止任意 Lean 源码、import、sorry、自动规划及自动重试。前置只做研究门禁，不注入假设。完整原问题和全部前提始终保留；不认证假设相容性或自然语言翻译正确性。

每个位置以固定 getGoals/ppGoal 读取实际目标。完整前缀仍有目标时，候选定理应因 unsolved goals 被 Lean 拒绝，父尝试可登记为完成了 OPEN 观察，但数学状态始终 UNKNOWN/E0。其他 tactic 错误不能当作有效下一状态。重建得到的历史目标文本必须与所选父状态一致；pretty 文本仅是诊断，最终 CLOSED/PROVED/E4 仍须完整类型/公理审计、具名语义核对及独立证明数据重放。

推演的 E4 不自动晋升原研究任务或知识库；原任务继续使用冻结协议独立管理证据。新代码不修改冻结验证器、旧研究图及固定观测实现，不重新封存运行环境。来源、原语境、计划、记录、祖先及检查工件漂移会持久失效，恢复文件不复活。取消、中断甚至成功 raw replay 后退出，也不自动晋升或重试。存储短暂忙碌不持久失效；损坏的独立空间或子账本应被隔离，避免阻塞其他工作。

最多50空间、每空间16次尝试、深度12；每次候选/重放共享1–30秒 worker，最多480秒，完整性扫描另计。使用原子摘要信封、fsync、短 flock 和既有全局 worker 锁。创建和后台扫描共用基目录短锁，扫描先取记录快照、释放锁后再审计或执行，避免读取尚未发布的记录。十四个主库不增加；备份须包含 artifacts/proof-steps/ 全部信封、隔离子 SQLite 及运行工件。

无新增依赖、模型、外部数据或 Euler 实现。作者可见基础例子只验收控制流程，不代表独立求解率、自动研究或四大期刊级原创数学能力。详见[协议](../protocols/proof-steps-v1.md)和[验收](../evaluation/proof-steps-results.md)。
