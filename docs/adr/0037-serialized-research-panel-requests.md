# ADR037：协调研究面板请求，有限恢复来源读取

日期：2026-10-28。阶段：MRA046。

MRA045 的浏览器验收有11次实际503响应。原任务、逐步推演、证据关联和续研在同一次渲染中各自请求；不同来源报告都可能短暂取得同一个原任务锁。并行读取导致页面自己制造锁竞争。读取还可能进行持久失效审计，不能用缓存或忽略审计解决。

新增仅供 /research 使用的页面内请求队列，四个面板的GET与POST统一串行处理。一个请求须完成JSON正文读取后才释放队列；不提前中止已发出的请求来开启下一个请求，避免服务端旧审计仍在执行。最多32份待发请求，不合并同URL请求，不缓存旧判断。

GET收到结构化503时最多再读两次，等待250ms和750ms；其他HTTP错误、网络错误或JSON解析失败直接交给原面板提示。GET可更新失效审计，因此这里的恢复只表示重读来源，不表示业务状态完全只读。全部POST只发送一次，包括预览、提案、保存、提交、撤销和取消；提交失败的用户手动重试沿用原请求ID。新代码在入队前固定POST正文，避免排队期间界面对象变化改动已核对内容。

项目/分支/节点渲染切换时递增语境版本，移除尚未发送的旧GET，丢弃已发送旧GET的结果并保持队列占用直到请求结束；旧语境的重读也停止。已确认入队的POST保留原URL与正文，不因后续导航改发到别处。原面板的提案与语义确认版本门禁继续执行。AbortError只表示被新语境替代，不向用户显示失败通知。

首轮实际浏览器发现初始化联动会使关联区停在加载态：推演目录完成时发出的空scope事件清除关联确认，同时误增来源读取的版本。关联区改用独立reading版本，只在重新加载来源或切换原任务/节点时使读取失效；确认版本仍由scope变化清除。修复后重新核对全部四面板。

页面提供来源读取状态，读取耗尽保留手动入口，逐步推演目录新增“重新读取推演记录”。一个来源仍失败时，其他面板成功不清除其局部失败提示。正在执行的任务沿用原有5秒详情读取；没有新增全历史轮询、证明重试、模型调用、共享后端缓存或跨浏览器锁。

全部数学源码、Lean/Mathlib内容、证据协议与历史结论保持原样；HTTP源码仅登记新静态资源。没有新增依赖。验证采用可控并发测试、实际浏览器与原真实E4工件再审计；本轮不重新执行生产RealTests，不将前端恢复计为新的数学证明或求解收益。

后续仍应以真实预算实验检验证明项复用，再按实际数学领域扩展接口。本轮修复已观察到的加载问题，不增加数学表达或自主研究能力。
