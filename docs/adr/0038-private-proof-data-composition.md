# ADR 0038：私有归档证明数据的显式组合

日期：2026-10-28。状态：核心与CLI经真实实验验收；网页/研究图桥接和独立预算收益仍待后续。

蓝图要求知识积累能服务后续证明。现有私有实例化重新检查原结构化证明输入；依赖续研只读取证据门禁，尚未导入证明项。不能把已有功能描述成可复用证明项组合。

比较两种实现：重新执行保存的证明源生成本地引理，或仅将已归档NDJSON证明数据重放到内核后引用。选择后者，避免运行归档Lean源与旧战术；固定基础环境及公理白名单保持。既有验证器、独立重放模板、归档/实例化协议和旧实验工件不改，新模式有独立账本。

输入为完整Nat目标、所有前提、1–4个有效私有E4归档和显式证明树。每次引理使用提供全部量化实参与前提证明；显示替换后的完整条件与结论，提交绑定具名确认及计划摘要。不替用户补充假设，不因归档状态直接赋予新目标PROVED。

候选进程读取归档证明数据，拒绝新增公理、unsafe/partial与未批准声明种类，为每个来源独立重命名全部本地声明及表达式常量引用，并由内核重放。独立桥接定理核对每个源的完整原类型。新目标必须引用明确的引理常量并完成候选审计；所有来源证明与新结果一同导出，由第二个不导入候选模块的进程重新内核检查完整目标。两个进程共享30秒以内worker预算。独立进程仍使用相同Lean内核实现。

来源版本、语义确认、归档字节、编译器、导入模板、基础环境和目标工件均绑定摘要。来源撤销/移除或漂移使新结果持久失效；恢复字节不恢复旧确认。临时锁忙应向调用方传播，不写成证据损坏。取消、中断、资源耗尽、类型不符均保持UNKNOWN；不会因证据失效声称命题为假。

退出条件：真实证明项组合的条件丰富正例、两个同名源定理的名称隔离、错误实参/错误前提的拒绝、来源撤销与损坏的持久传播、候选成功后独立重放中断不晋升；同时保全旧库和旧工件。测试生成与人工审阅记录必须区分协议检查与数学验证。此阶段不宣称模型、自主研究或顶级期刊难题求解收益；独立持出预算对照及研究图桥接仍需后续完成。

实际实验发现直接用 `Environment.ofKernelEnv` 替换环境后，后续命令丢失编译器realization状态。首轮保持REJECTED/UNKNOWN并保留日志。修复为在原Environment上按依赖顺序经公开 `Environment.addDeclCore` 核查每份安全声明及完整类型桥接，保持原编译状态；最终候选和冻结独立重放均通过。22项专项含同名隔离与错误类型/公理/中断边界全部通过，见[验收](../evaluation/lemma-composition-results.md)。
