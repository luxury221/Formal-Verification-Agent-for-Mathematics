# ADR042：预先审核完整证明程序的研究批次

日期：2026-10-28。状态：已验收；证据见 `docs/evaluation/research-campaign-results.md`。

组合成果已能再归档、再次真实导入，但旧研究图调度不消费新协议。继续增加只有关联标签的面板不能补足执行能力。本阶段提供独立研究批次：绑定原研究项目、研究线和不可变任务图，为每个节点明确选择完整现有组合E4，或完整新组合证明程序；统一具名核对图、原前提、输入和总预算后按拓扑执行。旧研究协议和证据判断保留。

新组合可显式引用私有成果库，也可用 `node.ID` 引用本批次已提交的直接前置节点。预览只使用前置的完整类型检查实参/原前提槽位，不伪造证明数据或宣称已证。执行时只解析该前置的具体检查工件与数据摘要；不得改写预先审核的目标、原文、变量、条件、证明项、预算或外部归档。每次导入仍走原受信数据模板，完整新目标继续真实候选检查与独立进程重放。

每个批次独立文件账本与子检查库，不进入主组合队列，不自动公开或写入成果库。原问题需自己的完整检查。子检查完成与图节点提交分开；监督退出后不从残余工件或已完成子记录自动晋升。原始检查可保留供审计，取消/中断批次不发布数学证据。直接/传递来源、前置绑定、原研究语境和实现变化持续停用后继，恢复字节或重发旧请求不能复活旧图。

批次最多8节点、50份，单次输入192KiB。一个项目worker锁，检查次数、预留worker秒数和墙钟限额需预先确认；每次开始保守计入完整单次预算，不退款、不悄悄缩短预算、不自动重试。墙钟在执行门禁及运行取消轮询检查，内容完整性扫描不能抢占。既有E4只重审计、不消耗新Lean检查次数。部分成功/失败/未知保留完整分母，未经完整检查的节点保持UNKNOWN。

测试须覆盖新旧组合混合、前置证明数据实际导入、全部原前提/错误证明、受控总预算、运行取消、监督退出后恢复、损坏恢复不复活、上下文和实现变更、忙锁、严格HTTP/CLI以及桌面/手机界面。作者证明不算模型求解率；一般定义、自主规划、独立同预算收益与真实模型仍需后续专门阶段。

联调修正：最初使用既有非阻塞记录锁，正常状态查询可与监督提交争用，导致后台 WorkerBusy 后被恢复流程视为中断。改为仅批次记录使用跨进程排他串行锁；不改变全局 worker 锁、旧研究锁或冻结执行器。锁内不执行 Lean，完整性复核和等待不承诺硬实时上界。新增并发读取/提交测试，失败批次与旧实现证据保留；实现变更后重新具名预审和执行，不修补旧指纹来保留“已证”。
