# ADR 044：测量后优化运行环境内容扫描

日期：2026-10-28。状态：初始实验前登记，以下决策按实际测量补充。

MRA052 的非 worker 耗时显著，不能直接将它全部解释成哈希开销。先对一次新的、真实完成候选和独立重放的检查作 cProfile，记录全部函数调用；剖析有开销，不能用其绝对时间证明提速。

首个剖析发现四次完整环境扫描为主项。原执行器和已有证据清单冻结，不减少扫描次数、内容范围或文件变化检查。优化只允许改变读取和遍历方式；每次仍从文件读取所有覆盖字节，核对原始 SHA-256、模式、目录、链接、固定文件、宿主依赖、快照及锁。

首先比较旧扫描与串行／2／4 线程的新遍历。三次交替测量结果：旧中位 2.8607 秒，新串行 2.8887 秒，2 线程 4.0134 秒，4 线程 8.3117 秒。该方案无收益，不进入默认数学验证。保留其源码和完整结果，首轮冷缓存时间单独可见，不删掉失败尝试。

第二候选使用每线程独立的 1 MiB 临时缓冲区，readinto 后只对本次读到的字节更新 SHA-256。保留打开前／后、读后及路径的完整文件 stamp 比对和 O_NOFOLLOW；缓冲区不保存可信摘要，不跳过下一轮内容读取。与原扫描逐项比较记录，并测试相同大小／mtime 内容替换、缺失／新增／权限／链接、读取错误及并发替换。

第二候选三次交替测量中，旧扫描中位 2.7927 秒，串行缓冲扫描 2.6467 秒，相差约 5.2%；2／4 线程仍更慢。这不足以支撑增加第二条数学验证路径的维护和信任成本，因此暂不接入默认检查器，也不复制执行器或重封存旧依赖。

交付只读 `runtime-audit` 诊断命令，报告完整扫描范围、实际字节、各树记录摘要和耗时，保存本次工件。它不执行 Lean、不签发数学判断、不更改快照；始终 UNKNOWN/E0。报告是当次观察的历史，不能据旧 JSON 声称当前环境仍有效。可显式选择 1／2／4 线程进行诊断，但数学验证继续使用原路径。

只有未剖析的完整 Lean 检查对照支持有意义收益时，才考虑新的具名数学验证入口；届时必须保留完整目标、原预算、取消／撤销／中断、两进程审计和来源绑定。不得通过修改冻结 integrity.py、verifier.py 或旧清单使历史证明自动升级或失效。

实验是单机工程性能诊断；不外推模型、数学求解率或原创研究能力。没有新依赖；Python 标准库的线程／文件 I/O／剖析器仅用于本地工具和核验。
