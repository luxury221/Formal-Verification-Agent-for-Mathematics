# ADR 0060：结构图目录原子发布

日期：2026-10-29。状态：采用。

MRA068真实浏览器在保存新图后，后台扫描曾在record.json写完之前发现正式structureflow目录。原读取器按缺失账本写入持续invalidated标记，导致一个未执行的有效草稿新图永久停用。工件保留缺文件原因和时间；不能把此情况称为证明失败，也不能删除标记复活原图。

决定：新增PublishedStructureResearchStore作为产品HTTP和structure-research-* CLI的创建适配器，继承冻结原研究图读写与数学检查功能，只替换创建发布过程。仍持有原base lease保证请求ID和容量检查串行；先在同一base下的.creating-structureflow-*目录完成计划、空子账本、SAVED_WITHOUT_LEAN记录，然后在同一文件系统rename到正式目录并fsync父目录。旧枚举器只识别正式structureflow-ID，因而不会把准备中目录当损坏图。

保存计划、schema、指纹、检查来源及数学执行器不变；新适配器不授予E4、不绕过审计。冻结旧StructureResearchStore本身及旧源摘要，避免用存储发布修复使历史数学证据失效。新公共HTTP及CLI创建路径使用适配器；直接调用旧低层create仍是历史实现，不声称其并发发布语义已改。已有目录、旧失效记录和数学结论不迁移、不修复复活。

准备失败的隐藏目录保留供检查，不自动重试或删除；它们不进入已发布图配额，仍可能占磁盘，需要后续明确的人工清理设计。发布后、返回前退出时，原request_id和完整正文可读到同一已发布图；不能重建或额外运行数学检查。原本地宿主并发写和文件系统信任边界不扩大为强事务或防恶意宿主保证。

新增确定性交错测试：在子账本创建期间运行原后台扫描与目录读取，正式列表不含半成品且不写invalidated；准备失败保持隐藏；rename后退出按同请求恢复；HTTP实际使用新适配器而完整数学计划逐字相同。测试不调用Lean。最终浏览器从已完成rfl拒绝和未执行泛化程序的断点续验；保留误停用图，另存新完整图，只执行先前尚未运行的程序。
