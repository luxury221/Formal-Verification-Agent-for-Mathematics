# ADR 0062：明确锁暂忙及有界、可取消的证据重读

日期：2026-10-29。状态：采用，实测与最终摘要另存。

实际旧组合报告的单次cProfile显示32次load_runtime，约2.40秒／总2.56秒用于清单解析／摘要；原图报告约0.87秒，空闲图／复用扫描约0.038／0.018秒。这是作者当前工作区的局部剖析，不代表全部硬件或HTTP等待。完整清单重复解析是成本来源，但修改integrity或source_manifest会改变已绑定可信源，不能以缓存既有数学判断或隐瞒版本变化改善体验。

比较两条路径：直接优化可信清单解析需单独版本迁移、输入字节／可变对象隔离和完整重新验证；当前HTTP／前端读取协调可保留冻结数学源与已有证据。此轮采用后者，保留前者的明确剖析依据。没有跳过内容扫描、扩展信任或宣称数学执行提速。

HTTP仅对原WorkerBusy异常返回503、code=WORKER_BUSY、retryable_read及Retry-After: 1。GET可标明可重读；POST标明false。其他OSError／RuntimeError／SQLite错误保留原503，不冒称锁暂忙；输入／同源错误保持400／403。

同页共享串行请求队列，明确暂忙GET最多8次请求，间隔250、750、1500、3000、5000、5000、5000毫秒，累计主动等待20.5秒。排队和每次实际HTTP审计耗时另计，因此不是20.5秒端到端硬时限。旧未分类503仍保留原最多3次请求／两次重读兼容行为；坏JSON、网络错误和其他状态不自动重读。全部POST始终最多发送一次，无论收到什么状态。

GET带调用时语境校验：出队、响应解析后和每次重读前检查；切换语境后丢弃尚未发出的旧GET及迟到响应，停止继续重读。已发送请求仍可在服务端完成，不把取消观察当中止数学执行。POST正文发送前冻结，不由语境取消而丢弃已确认操作。

等待时显示证据核对提示；原图暂忙隐藏旧判断并清旧执行确认，保留未定提交的原请求身份。恢复后重新运行原完整报告审计，当前结果才重新显示。长时间暂忙到上限后明确转人工刷新，不自动重发数学提交。组合读取沿用原隐藏旧判断行为，增加等待／完成提示。没有新外部依赖或模型调用。
