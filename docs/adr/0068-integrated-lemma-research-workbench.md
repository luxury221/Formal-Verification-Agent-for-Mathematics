# ADR-0068：在同一数学研究工作台接通局部引理闭环

状态：实施；2026-10-29。

已有递归规划、完整程序检查、独立导出和跨任务导入均在 CLI，原网页只支持较早图节点策略。新增 /typed-research/lemmas 子路由，复用原页面外壳、导航、安全会话、结构记号与有界读取协调器，在数学研究的第三模式提供规划与检查、独立导出、跨任务复用三个连续步骤。旧图任务的数学判断不会因独立程序或应用成功而自动晋升。

HTTP adapter仅分派既有三个 store 和既有 obligation-v2 planner，不复制或放宽证明执行器/类型/公理/来源门禁。增加 TaskPump 的三个可选队列并连接 canonical stores；服务会处理这些库中已确认的 QUEUED，恢复旧 RUNNING 只记 INTERRUPTED/UNKNOWN。三个队列共享原 worker 锁、两阶段预算与取消；没有 HTTP 任意 work/recover 或原始 proof.ndjson 文件接口。

所有 POST 沿用本地 Host、同源 Origin/CSRF、JSON重复键拒绝和192KiB上限。GET无副作用执行，不启动Lean；其中证据复核可持久标记已经失效的记录。原递归报告通过忙感知 reporter调用既有 gate，避免 WorkerBusy 被旧 RuntimeError catch误写永久失效。来源仍须完整当前E4，确认只绑定已预览的新完整陈述。

UI展示原文、全部变量、载体、运算、定义、原条件、完整形式类型、局部义务、实例项/条件证明、来源链及候选/重放预算。编辑目标、来源、独立语义或应用时清理确认；异步回应必须匹配 epoch。写入期间固定输入与请求ID，失败不自动重发POST，可手动用原信封重发。轮询和重新核对先隐藏旧记录，避免把旧E4用于新草稿。

从原证明到独立导出必须新标题/语义描述/具名确认，从导出到新目标必须明确全部原条件证明。应用仅允许相同载体/运算/定义，固定无环来源链；复用结果不能再作来源。具名仍为本地声明，两进程同一Lean实现；示例是作者机制样例，不是模型输出或原创研究评测。
