# ADR 0073：独立分析执行版本中的流式完整性检查

2026-10-29，MRA081。状态：保留为显式可选实验版本；两样本未证明稳定提速，真实观察及局限见验收。

A1 的真实运行显示文件完整性耗时可能远高于候选与重放 worker 时间。既有报告和分析环境已封存，直接修改旧 scanner 会改变其来源身份。因此新增 analysis-streaming-v1 执行版本与独立账本，输入继续使用 analysis-language-v1，不修改旧源、封存范围或运行树。

每次验证仍重新读取全部声明文件的实际字节，逐项比较 SHA256、类型、权限、链接及完整路径集合，不缓存成功结果。目录采用 scandir 和已见路径集合，较大文件使用两线程，最多八个待取结果；256KiB 线程本地缓冲。文件打开前后核对 inode、设备、类型、大小、mtime、ctime；O_NOFOLLOW 与 O_NONBLOCK 避免末端链接和 FIFO 竞争阻塞。目录遍历及异步读完成后检查状态，seal 开头和末尾重新读取。此检查不声称消除所有并发文件系统攻击或提供操作系统快照隔离。

新的 manifest 绑定新 scanner、执行器、扫描政策及旧可信来源；新旧计划指纹不同，完整数学目标和生成的候选/重放源码保持一致。独立的 analysis_streaming_identity、canonical/private 路径避免收养旧账本；旧服务不自动扫描。成功报告仍核实际环境、完整工件、条件确认、公理、不同 PID、NDJSON 和共享 worker 预算。性能指标仅为 E0 观察。

验收采用两道仓库已知目标新旧交错对照，每目标/profile 各一次，同为6GiB、512MiB swap与30 worker秒；完整性时间另计，记录所有验证调用、worker 和 whole-job 时间。两个样本不能支持通用提速保证，也不能把缓存、顺序或内存效应归因于 scanner。另做真实负对照、重放后取消、成功数据损坏恢复控制及旧证据只读复审。全部失败与超时保留，超时不是反证。

无新依赖、下载、模型、A2 import 或PDE能力。没有执行整体项目升级、迁移或恢复；新增版本可显式选择，旧来源保持。复制执行器会增加维护成本，后续公共化必须保留旧 provider 身份。实际数据见[验收](../evaluation/analysis-streaming-results.md)，命令与门禁见[协议](../protocols/analysis-streaming-v1.md)。
