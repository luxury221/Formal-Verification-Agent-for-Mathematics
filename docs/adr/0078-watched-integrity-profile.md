# ADR0078：独立的事件监视完整性扫描与 PDE 执行身份

日期：2026-10-29。MRA086。采用；实际验收结果另见本轮报告。

MRA085 的旧 streaming 扫描器在实际诊断中漏检同字节改写和目录新增；漏检时完整元数据戳相同。哈希只能描述读取内容，不能证明这段时间从未发生过又恢复的写入。不得用测试延时、反复重跑或成功缓存来掩盖这一限制。

新增 streaming_integrity_v2.WatchedSnapshot，每次完整读取封存范围内的文件字节，同时通过现有 Linux inotify 公共 API 观察文件 inode、目录和显式路径解析所涉及的名字。所有订阅装好以后才开始声明整体监视窗口；安装期间已经观察到的相关事件也拒绝。字节读取结束后重新枚举完整结构，复核目录/文件模式和链接目标，再排空事件至 EAGAIN。监视不可用、订阅不足、事件丢失/溢出、解析异常或有界排空耗尽均拒绝，无旧扫描器回退。硬链接对应同一 native wd 的规则须合并。

旧 streaming、PDE、微积分和分析来源及环境不变。新的 pde-energy-watched-v2 采用独立核心、元数据、run ID 和工件目录；复用原不可变 pde-energy-v1 Mathlib 树及原十二个已知案例，数学命题、条件和双阶段验证要求保持。新 profile 另绑定 ctypes/_ctypes、libffi、解释器及相关源码/缓存的实际宿主文件；版本、用途、许可通知与哈希见本阶段 dependency-review.json 和独立 adoption/acquisition。

本轮不安装或下载依赖；ctypes 为既有 CPython 标准库（PSF），libffi 为既有 MIT 组件，glibc 遵循现有 LGPL 通知。仅调用公共 API，不复制其实现。kernel release 作为新 profile 的显式上下文核对项；不擅改系统 inotify 限额。

这不是不可变 OS 快照，也不是恶意宿主防护。保证结束于最终事件排空，而非函数返回后；不保证所有内存映射或远程文件系统写入均产生事件。监视安装完成前恢复的修改不能因此被追溯。实际字节与结构校验仍保留，不把事件观察当作数学证据。

旧两项失败保留其历史状态；本轮旧测试偶然通过不能说明旧实现已修复。新版用实际事件、受控相同戳、瞬时恢复、别名写入、真实队列溢出及资源清理测试建立证据。新 profile 的已知目标检查不计为模型求解率或新的数学成果，不宣称稳定提速。后续目标仍为受控 PDE 新输入、确切引理应用、研究图与网页，以及真正的边界空间/弱形式。
