# ADR 0083：统一跨领域研究入口与显式验证交接

日期：2026-10-30。状态：采用。

## 问题与决策

逐个领域添加网页与例题不能使系统获得一般数学研究能力。用户要求加快开发并覆盖数学各领域，因此新增 `/studio`，以原问题、完整定义与假设、版本化依赖路线、多轮研究记录和验证反馈作为统一对象。11 类领域标签允许补充自定义方向，标签不是已实现的求解能力。

研究计划和研究步骤复用现有模型适配器，新增两种任务协议；模型配置沿用本地配置，当前不调用真实模型。未配置时可以保存问题、人工建立路线、记录推演及交接已有验证器。原 Nat 协议继续使用原提示。

## 证据与语义

研究文字、候选引理和模型操作完成一律 UNKNOWN/E0。最终研究步骤须逐字保留原题，不得增加最终目标的假设；条件性中间步骤须显式记录额外条件。保存完整形式化候选前，需要原题、定义、条件和全部目标的完整预览及具名确认；保存本身不执行数学检查。原题语义与形式化的对应仍依赖具名审阅，系统不声称自动证明自然语言翻译正确。

通过现有 typed、calculus、pde 后端执行真实检查。某候选 E4 仅属于确切形式化命题，不自动为其他研究文字、原题的所有分支或整个领域授证。反馈保留读取时刻和确切计划身份，后续研究可引用，但不是永久有效的新凭据。

## 运行与恢复

每问题最多 12 步、8 个计划、24 轮研究、16 次模型请求；单请求 90 秒、8192 输出 token。受总存储预算限制，完整上下文超预算时拒绝请求，不静默丢弃条件。模型调用期间持有传递给子进程的生命周期锁；取消后丢弃结果。恢复只能在取得该锁后将残留 RUNNING 标为 INTERRUPTED，必须显式发起新请求，无自动重试。

写操作具有请求身份与版本前提，验证交接使用稳定下游请求身份，提交研究记录失败后可显式恢复相同任务。前端不自动重发 POST。无任意 Lean 源码、脚本或命令执行，无新依赖，不改变旧验证器或重封存旧运行环境。

## 限制与下一重点

这一决策扩大研究工作流的领域范围，未扩大所有形式化后端的表达范围。一般拓扑、代数几何、概率与高维弱 PDE 等仍需逐步接入适当库和证明搜索。模型研究质量待用户配置服务后实测，不能用协议模拟代替。后续重点是真实题目的多轮推演、缺口诊断和证明库检索，避免以页面数量衡量数学能力。
