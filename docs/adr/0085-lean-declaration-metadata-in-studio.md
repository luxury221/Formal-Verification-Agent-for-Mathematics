# 0085 · 从封存 Lean 环境读取研究引用的类型

日期：2026-10-30。状态：采纳。

源码检索按词法提取候选，片段可能缺少前文的变量、宇宙参数和类型类。仅凭片段调用定理容易遗漏条件。因此增加显式的声明元数据读取，供统一研究工作台与后续模型推演使用。

采用项目自有静态 Lean 模板，从已导入环境枚举实际名称，并用实际定义模块与名称相等/后缀条件筛选。只把经索引核对的模块名插入 import；待查名称通过 JSON 数据输入。返回完整限定名、声明种类、宇宙参数、量化类型、显式应用参数版本、全部外层 forall 参数和结论。不展开所有定义。一个命中表示模块和名称筛选唯一；这不是按源码位置建立的编译器映射。多个命中全部保留为 AMBIGUOUS，不猜选一个。

复用现有 analysis-foundation-v1 的不可变 Mathlib 缓存和原 namespace 启动器。P0 小缓存不含 Heine–Cantor，而该分析缓存已有相关编译文件。没有新增下载、依赖或改动封存树；没有扩大任何原证明提供器的可接受 import/表达语言。每次实际读取前后完整验证现有分析快照，且实际执行树的被查源码必须与检索源码 SHA256 相同。缺少缓存时保留诊断，不自动下载/编译或重封存。

请求在启动后返回后台状态；为避开空闲队列轮询的短暂占锁，启动时最多等待 checker 锁两秒，仍繁忙则拒绝，不重试数学执行。子进程继承元数据锁和全局 checker 锁，Lean worker 继承后者，防止父进程退出后重叠执行。Lean 执行上限 40 秒（环境字节核验时间另计）；每个缓存身份最多三次显式尝试，全局最多 64 个缓存身份。运行中断、失败、超时不自动重试；重新读取必须由用户动作产生。运行记录、旧尝试和日志保留。源引用撤回或计划变更不会将旧元数据送入新步骤上下文。

缓存绑定索引身份、确切候选、分析运行时快照和 reader/template 的 SHA256。读取缓存核对记录、实际工件、模板、请求 JSON、报告和解析状态；不重复启动 Lean，也不在每次打开笔记本时重扫运行时全部二进制。缓存是历史读取结果，不能作为当前运行时完整性认证。reader 或快照身份变化需重新显式读取；元数据损坏不遮蔽原题与源码引用。

这些记录始终 UNKNOWN/E0。已有库声明的类型读取不会证明其适用于原研究目标，不产生 proof receipt、独立 replay 或新数学证据。模型收到元数据仍须保留全部原始条件，经既有形式化门禁获得目标自身的证据。
