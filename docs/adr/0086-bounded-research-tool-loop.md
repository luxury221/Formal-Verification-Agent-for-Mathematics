# 0086 · 让研究模型使用受控检索和表达预览

2026-10-30，采纳。

现有工作台能保存多轮推演、人工引用、真实 Lean 类型以及验证反馈，但一次 AI 推演只调用模型一次。模型无法主动把检索结果或表达诊断用于同一轮的下一次候选。新增有预算限制的研究工具循环，以推进可操作的研究流程。

模型可以返回最终研究提案，或带确切原题/计划/步骤身份的 JSON 工具请求。仅支持 `search_mathlib` 与 `preview_formalization`。检索复用既有固定源码索引，每次最多5候选并附已有的类型缓存；不自动读取新 Lean 类型、不下载或执行证明。表达预览复用用户选定的后端完整 graph preview，返回结构编译结果或具体诊断；不保存图、提交检查或宣称语义对齐。同名类型歧义保留。

一次推演最多4次模型调用、3次工具操作，共用90秒、8192输出token和128KiB模型输出字节预算；每次完整输入最多100000字符。整本笔记最多16次模型调用，旧单次操作按一次计数，模拟调用与真实模型分开。工具在独立进程中执行，与模型传输共享截止时间，取消/超时会结束子进程并回收；进程继承模型生命周期锁。90秒覆盖循环中的模型等待和工具子进程；原始上下文准备、归档I/O和文件读取另有开销，不将它当作整个HTTP请求严格墙钟上限。传输失败不自动重试。没有最终提案时，保留失败/取消记录与部分过程，不新增成功轮次。

每次请求/已接受响应/工具结果归档到原笔记本的操作子目录。笔记本仅保存调用计数、工具摘要及工件哈希，避免多次完整输入撑大主记录。开始新操作前预留完整循环与取消所需事件预算，并要求2MiB主记录上限下至少剩余256KiB空间；不足时在进入运行状态或调用模型前拒绝，避免最终候选与失败记录无法保存。读过程记录检查真实工件哈希；损坏过程不遮蔽原题。工具历史是当时的研究记录，不认证当前来源；下一次模型调用前重新核对本轮检索命中的源码，失效片段和类型不得带入可用上下文。

继续沿用原最终提案模式与人工完整预览/具名核对/显式真实检查，研究文字、检索和表达预览全部 UNKNOWN/E0。相同原题文本只保障身份，表达预览不证明自然语言与公式完全等价；这仍需语义核对。未配置真实模型时保持禁用，不临时替用户配置模型、不把固定脚本表现称为研究能力。

无新第三方依赖。封存验证器、运行时、Mathlib索引器和类型reader未修改。证据：`artifacts/research-tools-20261030-01/`。固定脚本仅验证协议：真实检索→拒绝替换原题→修正后实际表达预览→保存未验证提案，不评估开放问题求解能力。
