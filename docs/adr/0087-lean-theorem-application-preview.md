# 0087 · 用 Lean 预览定理对完整候选的应用

2026-10-30，采纳。用户要求暂不配置模型、继续优化。现有源码检索与声明类型缓存没有检查定理如何用于当前目标；纯字符串比较无法可靠处理隐含参数、类型类和前提条件。因此增加显式、受限的 Lean 元层应用诊断。

用户从当前步骤的有效引用中选择确切定理名，并选择已保存的完整 calculus/pde 形式化候选。后端复用实际 graph preview 编译最终节点，保留全部变量、假设与目标，不接受用户提供的 Lean 字符串；typed 定义暂不支持。定理名必须来自该来源已核对的 Lean 元数据，多个同名项由用户明确选择，definition/axiom 等不作为定理应用入口。

新仓库模板仅导入核对的 Mathlib 模块，用生成的完整类型建立局部上下文。Lean `apply` 推断参数，尝试用已有局部假设匹配子目标，返回隐含参数/类型类/显式参数及剩余条件；不增加假设，不执行一般证明搜索。返回 NO_OPEN_GOALS、OPEN_OBLIGATIONS、NO_MATCH，均 UNKNOWN/E0。没有剩余目标仍只是元层应用诊断，不生成定理声明，不做独立重放、公理检查或自然语言语义认证，不能转成 PROVED/REFUTED。

复用既有封存分析环境和隔离 launcher，执行前后完整审核，40秒 Lean worker 预算，完整性I/O另计；不修改原验证器、运行时封存或其证明导入政策，不下载或重封存。执行工件与缓存绑定确切原题、计划、步骤、完整候选、来源、完整限定名、元数据及新reader/template哈希。读取缓存逐件核对实际工件，不把缓存视作当前完整运行时认证。

笔记先原子保存请求引用，再争取执行资源；繁忙时保留 NOT_STARTED，用户可显式重发同一请求编号，避免偷偷重试。每本最多16次应用预览登记、全局最多64种缓存、每种最多3次显式尝试；同请求及已完成缓存不再执行。失败/中断保留旧尝试，生命周期锁与全局checker锁阻止并发检查。引用撤回、换计划、源码/候选/元数据漂移使诊断 UNAVAILABLE，保留原题和历史引用；失效内容不进入可用模型上下文。
