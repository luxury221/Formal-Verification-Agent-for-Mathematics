# 0088 · 全文原文索引与逐项推理义务

2026-10-30，采纳。用户希望检查整篇论文的推理。目前的单定理验证和研究笔记没有逐段原文索引，也不能用一个已证结论代表作者的完整论证。因此增加独立的全文论证账本，先支持 HTML 原文与人工整理，不调用模型。

导入保存标题、固定版本 HTTPS 引用、完整 HTML、内容摘要及可复算的原文块位置。标准库解析器只提取候选命题、定义、公式、段落、参考文献和图表说明，不执行原文，不加载其外部资源。HTML 有 1 MiB、元素/嵌套/块数量上限；这不是穷尽的语义解析，不提供自动 PDF 或 LaTeX 形式化。

每个原文块可整理为结论、作者步骤、外部事实、定义、实验、背景或待澄清内容。数学义务保存完整陈述、显式前提、原文依赖与解释；依赖必须已分类且无环。原文不可原地替换，换版本重新导入。编辑采用预期修订号、幂等请求编号及原子文件发布，保留逐修订历史；文件摘要不构成外部签名或不可变存储。

只引用既有 calculus/pde/typed 验证器的精确节点，不接收或执行任意 Lean。绑定需当前 PROVED/E4、完整目标及人工具名对应，记录计划、尝试、目标、原文与证明文件身份。完整义务对应还要求验证器原文与本义务逐字一致。人工对应仍为 local-assertion-only，未提供独立专家审核或身份认证。

GET 仅显示历史关联，不授予当前结论。显式 recheck 调用既有验证器读取与复核当前工件，不执行新 Lean 或证明搜索。前提编辑会改变传递依赖身份，使本义务和下游关联失效；改回旧文字不会恢复旧关联。损坏、撤销、替换或忙碌均保持 UNKNOWN。反例特例单列 finding，不自动授予原文完整 REFUTED。

一个精确结论可以局部 PROVED；尚缺前提时其步骤状态仍为 BLOCKED。author_proof_verdict 的 GAP_FOUND 表示本账本尚有核查缺口，不直接判定作者原证明错误。即使已列义务全部通过，也不证明义务提取完整，因此本版 whole_article_verified 永远为 false，全篇 UNKNOWN，不以数量百分比冒充全文证明。

新页面 `/articles` 与 `/v1/article-audits` 沿用现有同源、CSRF和固定资产边界；只有导入拥有单独 2 MiB JSON 请求预算，其他请求保持原上限。无新增运行依赖，不修改原验证器、Lean模板、运行时封存和既有证明工件。论文原文只保存在本机工件，无下载其代码或对外发布原文。
