# 0089 · 论文义务与研究、验证任务的完整连接

2026-10-30，采纳。用户要求补齐框架。原全文清单只能人工填写验证任务编号，无法从未闭合义务直接进入研究并回收结果。因此扩展原有全文账本，连接现有 Studio 和正式验证器，而不另建证明引擎。

`ArticleWorkflow` 负责连接，不决定数学真假。它从论文原文身份与完整义务、传递前提的版本生成快照，创建普通 Studio 任务与原题路线。原题逐字保留，显式前提完整传递；依赖另标为尚未验证的义务，不直接添加到数学假设中。完整上下文超过现有预算时拒绝创建，不静默截断。每篇最多 16 个任务。

任务引用保存在原文章记录的可选 `workspaces` 字段中。旧 v1 文件无需原地迁移；单项 annotation 请求的原始指纹格式保持兼容。新增批量 annotation 一次最多 32 项、一个原子修订，允许同批先声明后引用，整批验证无环及完整字段；任一失败不提交部分修改。既有权限、幂等、修订冲突与历史保留规则保持。

创建任务在文章生命周期锁内执行，Studio 创建与原题路线使用稳定幂等编号。若文章提交失败，重发相同请求能找回已创建任务，不创建第二本笔记；旧研究记录不被删去或恢复成另一个数学问题。原题或传递依赖变化使任务关联 STALE，恢复旧文字仍不能复活。Studio 不可用时保留论文原文并显示关联不可用。

回收证据只能选该 Studio 实际交接的候选、当前研究路线以及原文完整义务节点；不能填写任意成功图冒充当前研究结果。显式预览核对当前正式图、精确目标、尝试、证明文件和 E4，并要求其 original 与文章义务逐字一致。预览绑定文章修订、Studio 修订及全部证据身份；慢读取期间笔记变化或提交前目标/证明替换均需重新预览。具名确认后才写回普通 equivalent 关联；回写本身不执行证明，普通 GET 仍无当前证明判断，显式 recheck 按原验证器重新读取当前工件。

新增依赖分层、研究前沿排序及 Markdown 报告。前沿只根据已人工列出的依赖，优先所列前提闭合的义务，再按影响的后续义务数排序。它是待办建议，不是数学证明搜索或依赖穷尽性声明。图、报告和研究任务均不能使整篇论文自动认证。

页面复用 `/articles`，包含原文、依赖图、下一义务、研究任务四个视图。未保存编辑不用于新研究或绑定，页面保留编辑并要求先保存；读取失败清除当前证据展示与预览确认，避免继续展示旧结果为当前有效。导出支持精确 JSON 与可读 Markdown，原文 Markdown 特殊字符转义，不能借报告加载外部图片。

模型按用户要求仍未配置；可人工提供完整研究候选。没有新增依赖、任意 Lean 入口、验证器实现或运行时封存变更。真实验收用论文公式24进行新任务检查与独立进程重放，目的是验证完整框架连接，不把重复已知定理当作新数学能力。公式25与等号条件仍分别保留未完成义务。
