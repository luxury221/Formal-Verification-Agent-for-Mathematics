# ADR 0090：独立版本的分析证明组合

日期：2026-10-30。状态：实现；数学验收以本轮工件为准。

## 问题

公式25可行性实验中，完整命题能被既有类型语言表达，固定 `grind` 却无法证明。人工添加确切内积引理、平方改写及 `sub_nonneg` 后，同一目标通过真实 Lean 和独立数据回放。缺口在于平台缺少可组合的证明程序，不能靠增加界面解决。

既有 calculus 编译器、账本及研究图均被历史证据身份引用。就地修改会使原有 E4 记录失效，也不能把独立实验直接升级成平台证据。

## 决定

增加 `proof-language-v1` 和 `proof-project-research-v1`，后端名 `proof`。表达式和类型继承未改动的 calculus 语义；新编译器、执行账本、研究图采用独立文件、manifest、目录及账本身份。Studio 与论文账本只新增后端分派。

新语法提供：

- `have`：先证明声明的完整局部引理，再在后续词法作用域引用。禁止自引用及遮蔽原变量/假设；局部引理不能逃逸到并列分支。
- 受控定理规则：仅固定名称、参数数目和类型。Lean 继续检查实际定理应用及目标匹配。
- `rewrite`：明确列出允许的改写定理或已证明等式及方向，只使用 `simpa only`。
- `arithmetic`：固定 `linarith`、`nlinarith`、`ring`；算术事实显式给出。它们生成可供内核检查的证明，不增加公理或外部求解信任。

任意 Lean、imports、战术字符串、公理和占位仍不接受。沿用原请求总节点/深度/字节预算、40秒候选与回放共享预算、全局 worker 租约、取消和中断处理。局部引理随完整目标共同导出和回放，不以一段成功日志替代原问题证明。

复用已采用的 Lean 4.35.0 / Mathlib 56a005855ea17e0b0958f73ec801ae140b0a1679 与原 imports。新采用记录在 `.runtime/proof-language-v1/adoption.json`，保留许可、依赖版本及用途限制；不下载依赖，不修改旧封存树。

## 证据与生命周期

旧 calculus provider 源码、模板、运行时和身份保持不变。新 provider 的执行/研究生命周期以旧实现为基础建立独立版本文件；这种代码重复是保护历史身份的明确成本，后续若提炼公共实现，必须另开版本并复核，不能偷偷替换旧来源。

新账本和旧账本互不接纳，损坏的子账本不自动重建。保存/预览仍 UNKNOWN/E0；完整目标经真实检查、独立进程回放、精确类型、公理、工件及语义对齐门禁后才能 E4。损坏后的永久失效标记阻止恢复字节后复活。

论文回收沿用既有 Studio 实际交接、当前路线、完整原题和精确目标确认。旧失败候选及独立人工实验保留；新的平台证据必须重新执行产生。

## 范围

这是原有实分析表达范围内的证明组合扩展，不是通用 Lean 输入器、自动论文形式化、自动证明搜索或完整作者推理认证。来源与形式化的语义对应仍是具名本地声明，并非独立专家保证。验收报告位于 `artifacts/proof-composition-20261030-01/REPORT.md`。
