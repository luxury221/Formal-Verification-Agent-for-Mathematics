# ADR 0096：可观察的论文证据复核与人工研究回收

日期：2026-11-01。状态：采用本轮实现边界；实际服务与数学流程的验收另存工件，不由本决策记录授予。

## 问题

论文关联的验证任务可能包含耗时证据读取。把整次关联复核放在一个前台请求内，会使进度、取消与失败位置难以辨认；把缓存的逐图结果显示成实时证据，又会掩盖原文修订与工件变化。人工研究还需要同时保留完整原题和限定子题，不能把一个已证子题直接算作完整原题的证明或反证。公式阅读与同页导航必须支持这些边界，而不能改写原文或沿用旧确认。

## 决定：后台任务只管理历史观察

新增独立的文章证据复核队列与 worker，在固定文章修订的快照上按后端、任务图分组读取既有关联。快照绑定原文、目录、完整文章记录、修订与证据关联身份；每组读取前和最终发布前重新比对。worker 不提交新的数学检查或调用模型，不替代原 provider 的完整性核对，也不改写原文章的判断、关联或验证器工件。

任务执行状态与数学判断分开。`COMPLETED` 表示计划读取结束，可以包含不可用、繁忙或已变化的证据。匹配观察标记为 `MATCHED_AS_OF_CHECK`，仅描述对应图被读取时的结果；轮询、完成摘要和历史报告均不构成实时 `CURRENT` 授权。摘要只在当前文章快照及复核实现仍匹配时展示；历史结果即使可读，也不证明后续工件仍有效。使用或绑定数学证据仍须经过原验证器和原文章的现有检查。

网页使用新增持久任务接口表达进度、失败图与协作取消。旧的同步 `POST /v1/article-audits/{article}/recheck` 保留原语义，不静默改成异步响应；历史调用者可继续使用。任务编号、原请求体、文章修订与幂等关系保存在业务账本内。传输失败不证明业务未提交，网页不自动重发写请求。

完整契约见 [后台文章证据复核 v1](../protocols/article-evidence-rechecks-v1.md)。

## 决定：完整原题与限定目标分别交接、分别回收

人工 Studio 路线保留唯一完整最终原题，其陈述逐字等于原始问题，不因加入子题而增加原题假设。人工限定见证作为明确的 `lemma` 或 `subproblem` 连接到最终原题，保留自己的对象、前提和限制；研究依赖本身不构成数学蕴含。保存路线和推演不授予证明状态。

形式化候选的完整 `problem` 节点必须逐字对应本轮所选研究步骤。预览、实际 Studio transfer、验证器保存任务、显式执行检查及回收是分别记录的操作。回收必须追踪当前原文 workspace、study、当前路线 round、实际 transfer 及其确切形式化 `problem` 节点；不能挑选任意独立已证任务冒充这次研究产出。预览与绑定核对完整计划、原始文本、证据身份和修订，并在绑定时重新读取证据。

`equivalent` 要求被检查步骤保留完整原文义务；`counterexample_specialization` 只接受陈述不同的明确子题或引理，并记录具名审核人对限定反例关系的本地声明。任意已证子题不会自动成为反例，限定见证也不自动给完整原题授予 `REFUTED` 或 `PROVED`。自然语言到形式目标的数学对应仍需核对，不能以文本相等、指纹匹配或确认勾选代替语义责任。

审核人主动填写范围与限制并确认当前完整预览；切换关系或候选必须重新预览。新关联只追加历史，保留原题、条件、旧关联和修订。无 `relation` 的旧请求继续委托原 `ArticleWorkflow`，不重写已有记录与预览语义。完整契约见 [人工研究结果回收 v2](../protocols/article-research-return-v2.md)。

## 决定：本地排版与安全导航服务于核对

采用固定版本、本地分发的 KaTeX，先记录来源、完整性、MIT 许可、用途和限制，保留版权声明。只对明确标记的完整自然语言纯文本排版；保留完整原始文本 / TeX 切换，完整 Lean 命题、程序、JSON 和表单数据按原样展示。排版不参与数学判断。未知命令、不闭合分隔符、超限和排版异常回退原文。

原文不作为 HTML 执行，不请求原文资源或 CDN；禁止用户宏定义、HTML、链接、资源与文件命令，固定 `trust: false` 并限制展开、长度、数量及尺寸。静态资源采用精确路由白名单及正确字体 MIME。`/articles`、`/proof`、`/analysis`、`/studio` 仅为受控布局允许内联样式属性；脚本与样式元素继续限定本站，保留同源、CSRF 与禁止页面嵌入的约束。采用记录见 [KaTeX 本地排版依赖](../dependencies/katex-v1.md)。

证明 / 分析页同时处理首次深链与后续 hash 变化：先选择确切项目和分支，再读取对应任务，显示前核对报告归属。切换语境即隐藏旧结果并清除预览、确认与运行许可；过期读取、写响应、错误与轮询不能覆盖新语境。导航读取可继续，数学写操作仍由原确认与串行边界约束；导航不能触发自动数学提交或写请求重试。

## 失败、升级、回滚与容量

复核 worker 的独立生命周期 lease 覆盖读取、图间间隙及空闲期，其他进程不能将活跃 owner 当成崩溃进程恢复。provider 读取不持文章锁或任务锁；短锁只保护快照、进度、取消和发布。崩溃后未完成的步骤进入 `INTERRUPTED`，未提交引用的观察不被收编，不自动重读图或重试 provider。

每个任务保留创建时的复核、文章核对及原文处理实现指纹。升级或回滚时，旧完成任务保留为带原 provenance 的历史，实现不匹配则隐藏当前摘要；旧活动任务中断，已有取消请求保留。禁止跨实现续跑，即使变化发生在 provider 读取中或最终发布前。回到原实现不会重启已中断的终态任务；需要新任务时显式创建，不删除、改写旧工件或复活已失效数学证据。未来不兼容存储格式需要显式迁移。

损坏任务、异常引用、被重定向路径或不合法摘要按失败处理，可能阻断扫描、创建与队列推进；不跳过损坏记录来制造看似正常的汇总。历史占用总量和单文章容量；当前没有自动清理、归档删除或容量回收功能。达到预算后应诊断并制定保留与迁移方案，不能自动删除证据或无限新增任务绕过限制。

## 取消与关闭的实际限制

取消是持久的协作请求。排队中或图间任务可以立即结束；在途 provider 调用不能被此 worker 抢占，返回后在提交观察前重新检查取消。取消先提交则不发布完成摘要，完成先提交则保留已有历史。

服务关闭先通知两个队列停止接收下一项工作，再等待当前读取或检查退出并释放 owner。`close()` 同样不能强行中止 provider；其等待没有独立超时保证，实际耗时取决于原 provider 与操作系统。本轮没有提供整篇复核的时限承诺，也不将取消按钮或 HTTP 成功响应解释为在途调用已停止。

这些设计完善本地产品闭环；它们不表示已接入真实模型或 openJiuwen，不表示任意论文、任意数学对象或全文推理已经可以自动验证。
