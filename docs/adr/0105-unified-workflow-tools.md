# ADR 0105：统一工作流发现与生命周期工具

日期：2026-11-02。状态：已实现；不代表通用数学求解或 openJiuwen 已接入。

## 问题与范围

产品已有文档导入、全文自动处理、研究工作台、真实检查及证据模块，不能将其误判为需要重建整个框架。实际缺口是 ADR0095 的业务工具仅覆盖已有研究记录的部分操作；外部编排器无法从同一协议发起文档与全文任务，也缺少可机器读取的整体能力边界。

本轮优先接通已有工作流，不改写数学编译器，不增加第二个任务队列或证据库。把所有数学领域放进注册表也不会增加可表达目标或真实证明能力；数学后端扩展仍需逐个语言合同、来源与采用环境。

## 决定

- 保留 `product-tools-v1` / `product-tool-result-v1` 信封，11个旧工具的参数与业务语义不变，增加17个工具，总计28个。
- 新工具覆盖能力查询、文档导入/清单/状态/草稿/取消、全文任务创建/清单/报告/工件/取消/恢复，以及研究任务创建/清单/原问题起始计划。
- `mra/workflows.py` 提供 `product-capabilities-v1`；本地工具 `workflow.capabilities` 和 HTTP `GET /v1/capabilities` 共用它。文档和全文能力查询也共用各领域模块中的纯查询函数。
- 能力查询不创建业务目录、不启动 worker、不联网。模型配置和文件存在只作为可用性线索；HTTP 可附本服务 worker 快照，CLI 明确 `NOT_OBSERVED`。
- JSON 工具只入队或操作已有 store。worker 独立运行、按原轮询机制接管；没有内联 Lean、模型调用或新的隐式恢复循环。

研究模型生成与外部模型候选写入暂不加入通用工具：既有人工候选写入标注 `producer.kind=human`，不得将外部模型输出经该路径伪装成人工产物。页面和原业务接口保留原合同；后续需要独立、可追溯的外部候选来源合同。

## 状态、预算和错误

统一的是调用信封，不强行合并不同领域状态机。原始 `state`、`math_verdict`、`evidence_level` 保留各自语义。全文 `COMPLETED` 仅表示流程结束，原文仍 UNKNOWN/E0；形式候选的内核结果另列。

所有写工具沿用默认关闭的 `allow_mutations`；该配置是本地调用权限，不是用户身份认证。原始预算、版本、请求编号、人工确认与幂等由原 store 检查。`paper.resume` 只重新入队可恢复任务，不重建预算、不复活已取消任务，不隐式重复未知消耗调用。

提交后输出失败仍返回 UNKNOWN，不能承诺回滚；输出超限仍整份省略结果，保留 document_id/job_id/request_id 等回执。动作 request_id 必须保留，不能被报告中的创建 request_id 覆盖。重复提交使用完全相同的业务请求，call_id 不作缓存。

文档大文件继续使用现有 HTTP 上传。工具总输入仍限128KiB，不能因为增加导入工具而默默提高所有工具的限额。工件查询仍只接受注册且摘要匹配的 JSON 名称，历史原始工件不等于当前有效证据。

## 升级、恢复与回滚

不修改任何旧记录 schema、采用记录、数学编译器、Lean 模板或运行时封存。全文实现指纹原本覆盖全部 `mra/*.py`，因此这次框架代码更新也会使旧任务 stale；允许查看历史，拒绝跨实现恢复，继续工作须显式创建新任务。不得删除该指纹检查来制造平滑升级。

撤掉门面、能力查询或回退代码不应删除领域账本、原文、预算日志及检查工件。新旧原始任务仍按各自协议保留；不能以回滚为由将新记录或审核覆盖到旧记录上。运行中的检查仍由原 worker 的 lease、取消及进程回收机制管理，本轮不新增其执行实现。

## 验证与限制

使用真实 store、HTML 提取子进程、独立 CLI 进程和本机 HTTP 检查入口一致性、默认权限、重复请求、提交后失败、输出超限、取消、恢复、源版本与实现漂移、旧v1拒绝恢复及损坏工件。

不新增运行依赖或外部 SDK；不改 UI；软件合同通过不构成新增数学成绩。尚无真实模型端到端效果、openJiuwen运行验收、自动学习发布或多租户能力。整体模块结构和后续交付边界见[框架总览](../product/framework-overview.md)。
