# MRA070：证据暂忙读取恢复验收

日期：2026-10-29。范围：既有数学研究工作台的HTTP／串行GET恢复；数学核心、旧记录和原协议保持。证据目录：`artifacts/evidence-read-coordination-20261029-01/`；最终封存见该目录`delivery.json`，独立Windows复核另存`postseal-windows-recheck.json`。

## 实际问题与局部剖析

MRA069的真实网页等待曾出现GET503并超过旧重读窗口。本轮先停止旧服务，核对其2515项封存哈希，备份475份旧来源、400个SQLite账本和587份旧状态文件。

真实只读cProfile：原图报告0.870930秒，完整组合报告2.559409秒；后者32次`ContentSnapshot.load_runtime`约占2.402秒，主要为重复JSON解析／规范化摘要。空闲图worker约0.037684秒、空闲复用worker约0.018413秒。见`profile-f2bf69df9ecf48c68b6b90715d716e8c/`。这些是本工作区单次局部观察，未做吞吐统计。当前证据不支持“空闲扫描是主要成本”的最初推测。

直接改可信解析器会改变旧证据绑定的来源身份，需要单独版本迁移、可变对象隔离和完整重新核验。本轮先改善读取协调，未实施解析缓存或数学执行提速。决策见[ADR0062](../adr/0062-bounded-evidence-read-recovery.md)，接口见[协议](../protocols/evidence-read-recovery-v1.md)。

## 最终行为

仅实际WorkerBusy返回503及`code=WORKER_BUSY`、`retryable_read`和`Retry-After: 1`。明确暂忙GET最多8次请求，7次间隔250／750／1500／3000／5000／5000／5000毫秒，累计配置等待20.5秒。排队和每次实际HTTP审计另计，这不是端到端硬期限。未分类503沿用最多3次请求；坏JSON、网络及其他状态不重读。全部POST最多发送一次，正文在入队时固定。

GET在出队、解析响应后和后续重读前核对语境；旧排队任务和迟到响应丢弃。已发送HTTP仍可在服务端完成，取消观察不等于取消数学执行。原图刷新开始即隐藏旧判断、清旧执行确认、令旧复用观察失效；未定提交身份仍按当前报告核对。恢复后原完整报告审计成功才重绘当前判断，耗尽则明确人工刷新。
