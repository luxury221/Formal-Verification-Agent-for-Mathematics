# MRA-016 运行环境完整性验收

日期：2026-10-19。环境：WSL Ubuntu-22.04、Python 3.10.12、Lean 4.35.0，沿用固定 Mathlib commit。设计与限制见 ADR-004。

`python3 ops/scripts/seal_runtime.py` 完成官方归档与实际安装内容比对：17,925 个 Lean 文件、10,267 个源码文件、154 个缓存包解出的 2,310 个文件。最终快照记录 33,152 项目录/文件/链接，另含项目配置、启动器、获取回执和关键宿主 ELF 依赖。首次封存用时 29.491 秒。

`MRA_REAL_LEAN=1 python3 -m unittest discover -s tests -v`：31 项测试通过、0 失败、0 跳过，用时 120.406 秒。其中 4 项合同测试、12 项完整性测试、15 项真实 Lean 集成测试；黄金案例仍在一个方法内运行 10 个子案例。独立执行 `python3 -m mra benchmark`，10/10 案例通过。

新增回归覆盖修改导入文件且恢复原 mtime、删除文件、插入动态库、改变文件权限、越界符号链接、启动器变化、宿主依赖变化、缺失/改写基线、拒绝隐式重建基线、已加载快照的锁变更，以及安装文件偏离归档。可执行文件变化测试确认验证失败前不会执行 `lean --version`。

真实集成测试先获得实际 Lean 回执，再向实际 Mathlib 构建树添加一个临时动态库。旧回执晋升被拒绝，新检查返回 `POLICY_BLOCKED` 且无子进程返回码/审计结果，新后端初始化也失败。测试在 `finally` 中移除测试文件并重新验证环境，不修改任何已安装依赖的原始内容。成功证明的工件清单指纹与回执环境指纹也已核对。

固定案例接口还增加命题/形式化联合校验。测试验证调用者无法保持案例不变、另传改写后的命题、目标表达式或证明方向来绕过输入限制。

每个新回执记录完整性耗时与检查进程耗时。测试末尾的实际样本完整性检查约 2.7–2.9 秒，Lean 检查约 0.8 秒；证据门禁还会独立读取一次环境，因此完整调用比首版 P0 慢。这是本机局部样本，不作为跨机器性能承诺。

源码门禁通过 27 个 Python/JSON 文件（含本机生成的锁）；Ruff 0.12.0 的格式和 lint 检查通过。`python3 -m mra environment` 也已实测通过，初始化并验证当前环境约 2.945 秒。独立黄金基准及机器可读记录见 `artifacts/p0-benchmark.json`、`artifacts/runtime-integrity-validation.json` 和 `artifacts/runtime-integrity-environment.json`，完整测试日志见 `artifacts/runtime-integrity-tests.log`。

验收范围是受信宿主上的仓库案例及环境内容漂移检查。没有新增模型调用、自动形式化或任意 Lean 输入支持；上游独立来源签名、可复现构建、原子不可变环境、持久验签及完整宿主封装仍未实现。远端 CI 尚未运行。
