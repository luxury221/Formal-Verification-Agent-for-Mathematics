# 全文推理工作台 v1

现已支持从义务创建研究、查看依赖图、批量整理和证据回收，见[完整工作流](article-workflow-v1.md)。以下描述原文账本与既有证据规则。

入口：<http://127.0.0.1:8765/articles>。模型无需配置，本功能不执行新数学证明。

1. 导入最多 1 MiB 的 HTML 文件，填写论文标题及明确版本的 HTTPS 原文链接。当前不支持自动读取 PDF。原文保存后不可覆盖，换论文版本需要再次导入。
2. 从目录、关键词或候选命题筛选定位原文。索引只给出候选块，不能保证已经发现全部隐含推理。
3. 逐项保存内容类型、完整数学陈述、全部前提、依赖编号及对应说明。先保存前提，再引用它；自依赖、循环和未分类依赖会被拒绝。定义和实验不会获得数学证明状态。
4. 关联已有真实任务时，填写验证器、任务与节点编号，复制完整形式化目标，并具名确认原文关系。完整义务对应要求验证器的原始陈述与本义务陈述一致；更强定理的特化仍需人工解释。反例特例会独立记录，不自动成为原命题的完整否定证明。
5. 点击“复核关联证据”读取当前有效证据。普通打开/刷新仅显示历史关联，当前数学判断为 UNKNOWN。复核不重新运行 Lean；忙碌或证据不可用时不会授予结论。已证明的结论与依赖未闭合的作者步骤分开显示。
6. 导出当前 JSON 报告。报告绑定原文摘要、原文块位置与切片摘要、修订记录、依赖、完整目标、对应范围和本次观察；重新打开后仍需显式复核当前证据。

修改本义务或任何传递前提后，旧关联成为 STALE，需重新审查与绑定；恢复原文字也不会复活旧关联。并发编辑采用 `expected_revision`，冲突需刷新。每次编辑提供独立 `request_id`；相同内容幂等，换内容不得复用编号。每论文最多 600 次编辑、64 条证据关联；文件上限 2 MiB，全局最多 50 篇。达到预算须导出并另行整理，不能无限追加。

| 接口 | 用途 |
| --- | --- |
| `GET /v1/article-audits` | 列举保存的论文 |
| `POST /v1/article-audits` | 导入 `{request_id,title,url,html}` |
| `GET /v1/article-audits/<id>` | 原文清单、义务和历史关联，不复核证明 |
| `POST /v1/article-audits/<id>/annotate` | 保存完整义务、分类、条件与依赖 |
| `POST /v1/article-audits/<id>/bind` | 人工确认并绑定精确既有节点 |
| `POST /v1/article-audits/<id>/recheck` | 请求体必须为 `{}`，读取并复核已有证据 |

`claim_verdict` 表示该完整局部义务的结论；`step_status=VERIFIED` 还要求所列依赖均通过。`author_proof_verdict=GAP_FOUND` 表示核查缺口，不直接断言作者犯错。本版始终 `whole_article_verified=false`，全篇为 UNKNOWN；未提供全文认证。人工原文解释与语义对应尚非独立专家结论。局部真实验证不能外推为通用论文验证、原创难题求解或顶刊成果。
