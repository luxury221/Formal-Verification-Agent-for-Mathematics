# 从论文义务到研究、验证及结果回收

入口：<http://127.0.0.1:8765/articles>。沿用[全文推理账本](article-reasoning-audit-v1.md)，旧论文记录直接可读。

## 完整操作

1. 导入明确版本的 HTML，在“原文与义务”中按章节或编号定位，保存完整陈述、所有前提、依赖及解释。单条尚不明确的内容标为“需要澄清”。
2. 未分类的段落、参考文献和图表说明可勾选后批量整理，最多 32 处。批量功能不代替阅读，候选命题和公式需逐项梳理；引用条目不是已证数学事实。
3. 查看“依赖图”和“接下来做什么”。箭头文字列出所用前提，层次按人工记录的依赖排列。“可推进”表示所列前提已闭合，不表示依赖已经完整，也不表示该义务已证明。
4. 在数学义务详情选择研究方向，补充必要定义，点击“创建研究任务”。完整原题和前提进入已有研究工作台；尚未验证的前置义务明确标为待证，不能直接当作新假设。
5. “进入研究”在新标签打开 Studio。在那里人工保存推演、缺口和完整形式化候选，预览全部目标并交给已有验证器，显式执行真实检查及独立回放。模型配置仍可稍后完成；此流程不要求模型。
6. 回到论文详情，点击该任务的“查看可回收候选”。列表只显示它实际交接的候选；选择完整原义务节点后，点击“读取当前证据与完整目标”。无当前 E4、目标不对应或研究路线已变，均不能绑定。
7. 具名核对完整原文、全部假设、形式化目标和对应范围，再“关联回这一原文义务”。回写不运行 Lean；之后点击“复核关联证据”，查看整份清单中各关联当前状态。
8. 导出 JSON 或 Markdown 审阅报告，包含当前观察、缺口与精确目标。报告以导出时的观察为准；再次打开默认显示历史关联，不自动认证当前有效性。

## 生命周期和故障

- 修改义务或任何传递前提后，旧研究关联和旧证据都会失效；改回旧字句也不能恢复原确认。
- 打开历史研究仍可阅读旧推演；回收必须使用与当前义务对应的任务。完整语境过大时需人工拆分，系统不会偷偷删条件。
- 创建任务后文章提交失败，可重发完全相同请求，找回已创建的 Studio 任务。相同编号换内容会被拒绝；并发编辑须刷新当前修订。
- 保存前的编辑保留在页面；创建、回收或切换原文前先保存或明确放弃。当前读取失败会清除旧证据判断和确认，刷新后重新复核。
- 未证明、超时、运行故障、找不到候选和被撤销均不能成为 REFUTED。这个连接层不增加任何任意 Lean 或命令执行能力。

## 新接口

| 接口 | 请求/行为 |
| --- | --- |
| `POST /v1/article-audits/<id>/annotate-many` | `request_id, expected_revision, annotations[1..32]`；每项完整 annotation，全部成功才提交一个修订 |
| `POST /v1/article-audits/<id>/research` | `request_id, expected_revision, block_id, area, context`；创建一个完整原题的 Studio 任务，保存来源关系 |
| `GET /v1/article-audits/<id>/research-tasks/<workspace-id>` | 读取该任务实际交接的候选及当前路线下的完整节点编号，不复核证明 |
| `POST /v1/article-audits/<id>/research-preview` | `workspace_id, graph_id, node_id`；只读复核既有真实证据，返回完整目标及预览身份 |
| `POST /v1/article-audits/<id>/research-bind` | `request_id, expected_revision, workspace_id, graph_id, node_id, preview_fingerprint, reviewer, scope, confirmed`；重新核对后关联回原文 |

文章响应新增 `workflow`、`workspaces`、`review_markdown`，包含原文整理数量、依赖分层、前沿、任务状态及可读报告。它们不提供全文认证。单次 article 操作的 `model_calls/new_lean_executions` 不累计所有外部 Studio 和验证器的历史工作；真实运行记录仍保存在对应任务中。

原有 `claim_verdict`、`author_proof_verdict`、证据等级与反例特例规则保持。全文始终 UNKNOWN；即使所有已列义务通过，仍需证明义务提取和作者推理映射完整。
