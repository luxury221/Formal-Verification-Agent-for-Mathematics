# 论文导入：源文件优先

本阶段将原始论文整理成可对照、可修正的结构草稿，入口为 `/documents`。
不需要配置模型；导入不会调用 Lean。数学状态始终为 `UNKNOWN/E0`，
`whole_article_verified=false`。

## 使用

1. 点击“导入论文”，填写标题。可填写确切版本的 HTTPS 来源链接。
2. 优先上传 UTF-8 HTML 或 LaTeX。LaTeX 可选择多个文件或文件夹，
   再选择主文件；仅上传 `.tex`，不编译，也不下载图片、宏包或参考文献。
3. 同时上传同一版本 PDF，用于原页对照。没有源文件时读取 PDF 文本层，
   文字不足的页面按选项尝试本地英文 OCR。
4. 在“全文结构”“待核查清单”“待处理”中筛选片段，查看原页、原始
   TeX 或 HTML、提取文本及显式引用候选。原页支持翻页和放大。
5. 修改文字、分类和说明后保存。原始提取保留，修正累积到新修订。
   “已核对提取”仅记录文字核对，不确认数学语义、公式正确性或证明。
6. 导出 JSON 保存当前结构与清单。填写来源链接后，可另建一个固定版本的
   全文整理记录，继续分类完整验证义务；它不会替换已有论文或授予证明。

提取在后台运行，刷新可续查；取消、关闭或崩溃中断不会发布半成品。
失败或中断后需显式重新导入，旧输入和诊断保留。重启服务不会自动把残留
文件标为成功。新建导入会清空上次文件选择；网络响应丢失后的同页写请求
保留业务请求 ID，服务端拒绝同 ID 对应不同内容。

## 优先级与范围

| 输入 | 内容来源 | PDF 的用途 |
| --- | --- | --- |
| 可索引 HTML + 可选 PDF/TeX | HTML | 渲染、文字匹配建议；不触发 OCR |
| 无可用 HTML，有可读 TeX | 选择的 TeX 主文件及已上传子文件 | 渲染、文字匹配建议；不触发 OCR |
| 无可用源文件，有 PDF | 各页文本层；不足时 OCR 或标待处理 | 固定原页 |
| 只有 HTML/TeX | 源文件 | 不提供 PDF 页码或缩放 |

HTML 复用既有结构索引。TeX 识别章节、常见定理/定义/证明/公式环境及
部分 `label/ref`；限于已上传的相对路径 `input/include`。保留未展开宏、
缺失或循环引用和未被主文件使用的文件提示。自定义宏、复杂环境及排版
可能使分类不完整，原始内容仍可查看。没有执行 TeX，也没有对整篇论文
做完整语义解析。

清单是规则识别的定义、结论、证明、公式和引用候选，**不穷尽全部前提、
推理或证明义务**。TeX 显式引用是依赖候选，不是依赖已成立的证明。
PDF/OCR 可能合并多个逻辑步骤、丢失数学字符；OCR 英文词置信度不是公式
准确率或数学置信度。PDF 页码匹配可能有多个候选或完全未定位，页面明确
显示“建议对应”或“待定位”，不声称源文件与 PDF 已认证为同一语义。

## 本地环境

在 Linux/WSL 项目根目录执行：

```bash
python3 ops/scripts/prepare_document_runtime.py --with-ocr
python3 -m mra serve --port 8765
```

省略 `--with-ocr` 可只准备 PDF 文本和渲染。仅导入 HTML/TeX 不要求 PDF
运行环境。OCR 准备脚本针对 Ubuntu 22.04 amd64，固定包版本需要本机 apt
索引仍可查到；不支持该环境时可关闭 OCR。依赖均置于项目
`.runtime/document-ingestion-v1/`，下载缓存位于项目 `.cache/`。
版本、用途、许可与再分发限制见 [依赖记录](../dependencies/document-ingestion-v1.md)。
本流程不准备高级数学验证 profile。

## 数据与资源边界

- PDF 最多 16 MiB、1–60 页；源文件最多 16 份、UTF-8 合计 1 MiB。
- 草稿最多 1500 个片段、512 Ki 个提取字符；单片段最多 48000 字符。
  字符预算不等于 UTF-8 字节预算；持久化元数据还受 2 MiB 上限约束。
- 渲染长边最多 2200 像素，原页图片合计最多 100 MiB。
- 文档子进程地址空间 2 GiB、CPU 120 秒、父进程墙钟 300 秒；单页 OCR
  35 秒。隔离进程和资源上限不等于面向恶意用户的容器或多租户沙箱。
- 保留最多 30 次导入，每份最多 300 次修正、12 份全文整理快照；总记录达到
  2 MiB 时提前拒绝新修正，保留上一可读版本。
- 本版不提供导入删除/归档界面。导出 JSON 不会释放容量，也不包含 PDF、
  源文件和 PNG 的完整备份；不能将“导出后再导入”理解为自动腾出空间。

原始文件、输入哈希、任务、完整草稿、逐页 PNG 和修订历史保存在
`artifacts/document-intake/document-*/`。`inputs.json` 绑定原始字节；
`record.json` 记录状态、修订与导出；`extracted/` 仅在成功后发布；
`.work-*` 保留中断诊断但不是可用结果。原文件、草稿或图片哈希不匹配时
拒绝读取对应内容。备份应在停止写入后保留整个目录及关联论文数据。

队列有独立进程租约，解析子进程继承该租约。取消和关闭会终止其专用
进程组并回收解析器，包含解析器先退出但 OCR 后代仍存活的情况。
服务端和本机文件所有者属于可信基础，哈希不能防止有权限者整体改写。

## HTTP 合同

写请求沿用工作台同源 Origin、Host、CSRF 和严格 JSON 检查。
`POST /v1/documents` 最大 HTTP 正文 24 MiB，PDF 用 base64 传输；源文件
正文按 UTF-8 保存。上传 HTML 仅按文本显示，不在浏览器执行。

| 路由（`/v1/documents` 下） | 用途 |
| --- | --- |
| `GET /`、`GET /capabilities` | 任务列表、本机工具可用性提示 |
| `POST /` | 固定输入入队；带 `request_id` |
| `GET /{id}`、`GET /{id}/draft` | 状态、成功发布的结构草稿 |
| `GET /{id}/sources/{index}` | 原始 UTF-8 源文件；从 0 编号 |
| `GET /{id}/pages/{page}`、`GET /{id}/original-pdf` | 从 1 编号的页图、下载原 PDF |
| `POST /{id}/cancel` | 空对象；终态后不改写结果 |
| `POST /{id}/review` | `request_id`、`expected_revision`、片段、文字、分类、说明和核对标记 |
| `POST /{id}/article` | `request_id`、`expected_revision`；创建未分类论文快照 |

表中列表和新建的实际路径为 `/v1/documents`，不带尾斜杠。
修订冲突要求重新读取；幂等重试不恢复旧修订、不复制新证明，也不自动
提交模型或验证器。取消赢得终态提交时不发布草稿，完成先提交时保留完成。

设计见 [ADR 0098](../adr/0098-source-first-document-ingestion.md)。本机实测
证据见 `artifacts/document-ingestion-20261101-01/REPORT.md`；该目录忽略 Git，
仓库克隆不含用户论文或本机运行环境。
