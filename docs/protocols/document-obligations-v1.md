# 从论文原文到完整数学义务

入口：`http://127.0.0.1:8765/obligations`。也可从论文导入页点击“整理数学义务”。
本阶段支持人工整理及真实验证回链；尚未自动理解整篇论文。

## 操作

1. 从已完成提取的论文建立固定版本记录，保留原文件摘要、原始提取、修正内容、片段位置和页码建议。
2. 左侧选择原文片段，以“原始陈述、定义、条件、证明、上下文”角色添加到右侧义务。多个片段可以共同支撑一个义务；同一片段也可以拆成多条义务。
3. 填写对象与类型、定义、量词、全部前提、完整结论、引用、前置义务和待澄清问题。引用与依赖并不自动成为已证事实。
4. 保存后先核对所用片段的文字与公式，再展开完整数学陈述，具名逐项确认七类语义对应。有未解决问题时不能接受。
5. 建立研究任务，进入已有 Studio，编辑完整形式化候选并预览、转交，再显式提交真实 Lean 检查。语言无法表达时应保留缺口，不能缩小原命题。
6. 在义务页选择该研究任务实际转交的完整目标，复核真实检查工件和对应范围，具名回链。当前支持回收 PROVED/E4；辅助引理、无关任务和局部特例不能冒充完整义务。回链后点击“复核这条义务的当前证据”，完成本次工件复核后才显示当前结果。

文字提取确认和语义接受均不产生数学证明。回链后只给这一条完整义务当前结果，
全文仍为 UNKNOWN/E0、未验证；不据此认证作者的每一步推导。

## 修订、撤销和历史

- 编辑任何数学字段、来源或传递依赖会建立新义务版本，旧审核及研究对应失效。恢复旧文字也不会恢复旧版本的确认；保存完全相同内容不增加版本。
- 撤回提取确认使相关语义接受失效；重新确认提取后仍需重新审核语义。
- 拒绝或撤销语义接受不会恢复更早的接受事件；只有原具名审核人可撤销其当前接受。
- 原文导入记录修订后，旧整理记录只供历史回看。请从新版本建立新记录，不迁移旧确认或证据。
- 普通读取与刷新只显示历史链接 `NOT_RECHECKED`，当前数学状态为 UNKNOWN/E0；不会自动启动耗时的工件核查。显式复核通过后，仅本次响应及其导出显示当前 PROVED/E4；再次刷新恢复待复核。复核不重新执行 Lean，但会核查原验证器、完整环境与工件，可能需数分钟。
- 复核沿用原有独立证据读取器，每个验证图限时 300 秒；同次请求内复用同图的读取结果。超时、忙碌或不可用不会授予当前结论。读取期间原文或义务修订改变时，丢弃本次观察。
- 审核人姓名只是本机具名声明，不代表账户认证或独立数学专家审核。

## API 与模型候选合同

`GET /v1/obligations/catalog` 给出字段、来源角色、确认项和限制；
`GET /v1/obligations` 列出记录；`POST /v1/obligations` 使用
`request_id, document_id, expected_document_revision` 固定原文版本。
`GET /v1/obligations/{dossier_id}` 返回固定来源、语义状态和完整历史，可导出 JSON；已有数学证据均为待复核历史，不授予当前已证。

以下均为 `POST /v1/obligations/{dossier_id}/{action}`：

| action | 用途 |
| --- | --- |
| `save` | 保存结构化完整义务，或建立新版本 |
| `source-review` | 对固定片段确认或撤回提取核对 |
| `review-preview` / `review` | 预览完整来源对应；接受、拒绝或撤销语义 |
| `research` | 转交精确完整目标到 Studio，保存任务但不执行验证 |
| `research-tasks` | 列出该任务真实转交的候选，仅列完整目标节点 |
| `evidence-preview` / `bind` | 复核当前原验证器证据并具名回链 |
| `recheck` | 以 `{"obligation_id":"..."}` 显式复核一条完整义务的已绑定证据；不修改整理修订 |

修改携带唯一 `request_id` 与整数 `expected_revision`，只读预览和 `recheck` 不需要。
相同修改请求可幂等重读；
编号复用到不同内容会拒绝。所有 POST 沿用本机同源和 CSRF 守卫，预览也不授权执行。

模型未来可提出与人工编辑相同的结构化候选，但仍须经过上述审核和验证。
`automatic_semantic_generation=false`、`model_calls=0` 是本阶段实际状态，
不能将字段校验或人工接受称为模型已完成自动形式化。

## 限制与备份

每份记录最多 64 条义务、160 个义务版本、240 次修改、24 个研究转交、32 条证据链接。
每条义务最多 24 个来源引用、32 个前置义务；确定性完整陈述上限 8000 字符，
各后端可能有更严格限制。超限明确拒绝，不自动截断。
源快照与记录各受原子 JSON 的 2 MiB 限制，记录数上限 30。
Studio 仍受原有研究项目容量、候选数量、执行预算和表达能力限制。

数据在 `artifacts/document-obligations/dossier-*`；备份时应停止写入，并连同
`document-intake` 原文件、`research-studio`、研究账本和实际验证图、子账本及证明工件一起保存。
单独导出的 JSON 是可读记录，不足以重建原验证器的执行授权。

本机真实示例：*Cauchy–Schwarz Regularizers*（arXiv 2503.01639v3）完整 Proposition 1，
包括非负性、零点集合双向等价及任一零向量情形。证明数据来自人工整理，本轮已重新完成真实 Lean 检查与独立进程数据重放；
此例不能代表自动语义生成效果或全文覆盖率。
