# 研究面板来源加载 v1

范围为 /research 页面的原任务、受控推演、具名证据关联、依赖续研四个面板。同一浏览器页面使用一个队列；不改变HTTP接口、后台worker或数学证据语义。

| 场景 | 行为 |
| --- | --- |
| 并行打开多个面板 | GET/POST按入队次序串行处理，完整JSON读取结束后才释放请求槽。最多32份待发请求。 |
| 来源暂忙 | 仅GET的结构化503最多再读2次，间隔250ms和750ms；无缓存、无请求合并。 |
| 重读仍失败 | 失败面板保留手动重读；共享状态仍提示部分来源未载入，其他面板可继续加载。 |
| 400/404/409/500、断网或坏JSON | 直接交由面板提示，不自动重读。 |
| POST失败 | 所有POST均只发送一次，包括预览与提交；用户明确重试才再发，原提交协议保持请求ID幂等。 |
| 排队期间编辑输入 | POST正文在入队前序列化固定；服务端仍核对完整计划、语境与具名确认。 |
| 切换项目、分支或节点 | 取消尚未发送的旧GET；已发送GET等完成后丢弃结果，不恢复旧确认；停止旧语境的重读。 |
| 已确认操作后导航 | 已入队POST继续使用原确切URL/正文；不因导航重定向、不自动重复。 |
| 多浏览器或外部CLI并发 | 不提供全局互斥保证；服务端仍可能返回暂忙，超出重读限额需手动处理。 |

GET报告可能持久记录证据失效；有限重读不会执行Lean、调用模型、创建证明尝试或晋升未知结论。检查提交、取消、撤销和已证判断继续遵守各自冻结协议。共享状态提示读取进度、重读次数及局部失败，不将成功载入解释为数学证明。

传输模块在四个面板之前加载，供其API适配使用；其调试snapshot仅含队列与恢复计数，不含正文、密钥或数学资料。保留已入队POST针对同一页面内的项目/节点切换；完整刷新或关闭页面可丢失尚未发送的请求，不提供持久队列，也不等于取消服务端已经接收的任务。单次后端审计耗时决定排队等待，本轮未新增服务端超时。

见[ADR037](../adr/0037-serialized-research-panel-requests.md)与[实测](../evaluation/research-loading-results.md)。
