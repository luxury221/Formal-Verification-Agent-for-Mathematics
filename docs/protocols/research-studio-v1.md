# research-studio-v1

入口：`http://127.0.0.1:8765/studio`。本地 API 共享已有 Host、Origin、CSRF、JSON 大小和类型守卫。研究记录存放在 `artifacts/research-studio/study-*`，使用原子持久化和目录锁。

## 操作流程

1. 填写题目、完整问题、领域、定义和全部条件，保存原题。领域可自定义。
2. 选择 AI 规划（须配置模型）或从原题建立步骤，编辑完整依赖路线。原题不可被缩小，最终步骤不能增加条件。
3. 选择一个步骤进行 AI 或人工推演，保存具体论证、未证明的缺口和后续行动。可以多轮继续，原记录保留；JSON 可导出。
4. 若现有后端能表达该步骤，附加完整图候选。展开完整预览，核对每个对象、定义、条件、目标和预算，具名确认后保存待验证任务。
5. 打开确切验证任务，按既有后端再次确认并显式提交真实 Lean 检查。保存候选不会执行检查。
6. 返回研究入口读取验证反馈。后续模型输入包括完整原题、当前路线、同一步最近两轮推演和最近两条反馈。超预算会拒绝，保留原条件。

模型未配置时按钮禁用，人工流程可用。模型调用可取消；崩溃后的恢复要求生命周期锁已释放，不恢复执行、不自动重试。

## API

`GET /v1/studio/catalog`、`GET /v1/studio`、`POST /v1/studio`、`GET /v1/studio/{study_id}`。

以下为 `POST /v1/studio/{study_id}/{action}`：

- `scaffold` / `plan`：原题占位、保存完整路线。
- `round` / `generate`：保存人工推演、请求有预算的模型规划或研究。
- `cancel` / `recover`：取消请求、确认已中断请求；恢复不会重新调用模型。
- `transfer-preview` / `transfer`：完整形式化预览、具名保存现有验证任务。
- `evidence` / `feedback`：实时读取绑定后端报告、记录读取时刻的反馈。

修改携带 `request_id`、`expected_revision`；相同请求内容可幂等重读，不同内容复用编号会拒绝。取消与恢复绑定 operation_id。预览、读取不授权新的数学执行。

## 能力边界

模型规划及推演跨领域，但需要真实模型配置并另行评估质量。当前形式化范围由既有三个受控后端决定，不能以领域标签或模型自报升级证据。整个研究记录保持 UNKNOWN/E0；确切形式化候选按原后端检查和语义审阅后可获得证据。允许人工审阅不代表独立专家审核。

单问题：12 步、8 计划、24 轮、16 模型请求；单调用：90 秒、100000 输入字符、8192 输出 token、131072 输出字节。整体记录还受 2 MiB 原子存储限制。单次失败不会触发自动重试或把旧结果作为新证据。请导出记录后继续新问题，当前没有自动拆分、迁移或无限运行。

可用的形式化后端：数域与显式定义（Nat/Int/Rat）、受控分析与微积分、受控经典一维 PDE。后端无法忠实表达时保持未验证，并明确缺少的表示。
